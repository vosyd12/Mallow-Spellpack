# 속성별 착지 파티클과 애니메이션

작성일: 2026-11-08. 범위: 슬라임 착지 효과의 이미지·재질·Particle System Prefab. 사용자 C#은 수정하지 않았다.

## 요청과 문제

슬라임의 크기를 키워 외형 식별은 어느 정도 해소됐지만, 착지에서 속성의 성질이 충분히 전달되지 않았다. 이전 반짝임·번개 셰이더는 밝기와 장식에 집중했고, 속성에 맞는 형태·움직임·소멸 과정이 부족했다. 사용자는 기본 표현부터 구현하고 부족한 연출을 더하는 방향을 선택했으며, 6종 시안을 바탕으로 MCP에서 직접 확인하며 적용하도록 요청했다.

## 선택한 방법과 달라진 점

기존 `SlimeMotion → LandingDustPool → LandingDust` 호출과 속성별 풀 6개를 유지했다. 새 게임 클래스·Update·코루틴 없이, 공중 입자와 바닥 프레임 애니메이션을 기존 Prefab에 구성했다.

| 속성 | 현재 표현 |
| --- | --- |
| 무속성 | 접촉 너비에 걸쳐 좌우로 퍼지고 커지며 사라지는 먼지 |
| 불 | 발밑 양쪽에서 솟고 줄어드는 불꽃 + 상승하는 불씨 |
| 물 | 넓어졌다 끊어지는 파문 + 튀었다 떨어지는 물방울 |
| 땅 | 낮게 튀는 돌 + 바닥에서 구르며 흩어지는 흙먼지 |
| 바람 | 열린 곡선이 휘감기고 풀리는 바람 + 작은 바람 조각 |
| 번개 | 바닥을 따라 뻗고 끊어지는 황색 방전 + 작은 접촉 스파크 |

- `LandingAnimationAtlas.png` 한 장에 5속성 × 6프레임과 공중 입자 6개를 넣었다. 실제 출력은 1254×1254이며, 209×209 셀 36개를 Unity Sprite로 분리했다.
- `ElementLandingParticles.mat`는 기본 URP Particles/Unlit, 알파 합성, Flipbook Blending을 사용한다. Renderer에 Position·Color·UV·UV2·AnimBlend를 연결해 프레임 사이를 혼합한다. [Unity 프레임 혼합 설명](https://docs.unity.cn/6000.2/Documentation/Manual/urp/particles-unlit-shader.html)
- 바닥 효과는 속성별 자식 Particle System 한 개로 구성하고, 6프레임을 수명에 맞춰 한 번 재생한다. 번개 0.44초, 물 0.64초, 불·땅·바람 0.56초는 현재 조절용 설정값이다.
- 부모 공중 입자 수명은 0.74초로 자식보다 길다. 기존 종료 콜백이 자식 효과를 중간에 끊지 않도록 했다. 부모의 짧은 방출 구간을 포함하면 반환은 재생 후 약 0.8초다.
- 공중 입자는 기존 C#의 크기별 개수·착지 강도·공격 확산 보정을 받는다. 바닥 애니메이션 크기·수명은 속성별 고정값이며 공격 착지라고 별도로 확대되지는 않는다.
- 이전 중립 파동 자식을 속성 애니메이션으로 교체했다. 새 효과는 이전 커스텀 반짝임·번개 셰이더를 사용하지 않는다. 과거 재질·셰이더 파일은 삭제하지 않았다. Bloom·Blur·카메라 효과는 추가하지 않았다.

실제 화면에서 불꽃 밑부분이 발보다 낮게 보이는 것을 발견해 자식 위치를 올렸다. 공중 입자가 몸에 가려지는 문제는 방출 위치를 발밑으로 내리고, 무속성은 넓고 낮은 Box 방출로 바꿨다. 파문·먼지는 배경이 보이는 빈 공간을 유지하도록 구성했다.

## 조절 위치

| 조절 대상 | 위치 |
| --- | --- |
| 전체 착지 효과 | `Assets/Prefab/Effects/LandingDust{속성}.prefab` |
| 바닥 크기·수명·표시 위치 | 자식 `{속성}GroundAnimation`의 Main / Transform |
| 재생 프레임 | 자식 Texture Sheet Animation → Sprites / Frame over Time |

| 프레임 혼합·합성 | `Assets/Materials/Effects/ElementLandingParticles.mat` |

## 실제 확인과 한계

- MCP로 기존 상태를 확인한 후, Medium 6속성을 같은 위치·착지 포즈·카메라 크기 4.8에 놓고 전후를 캡처했다. 난수와 입자 배치는 동일하지 않으므로 픽셀 단위 비교는 아니다.
- 실제 `SpawnLandingDust(false)` 경로로 6종을 재생하고, 0.04·0.10·0.18·0.28·0.40·0.56·0.68·0.84초의 변화와 소멸을 캡처했다. 이 시간별 자료는 정지 포즈에서 Particle System을 수동 진행한 재현이다.
- 공격 착지 호출에서는 번개 외 부모 입자 44개, 번개 부모 스파크 1개, 5속성 자식 바닥 효과 각 1개를 확인했다. 44개는 이번 Medium 설정의 결과이며 전체 크기의 고정 규칙이 아니다.
- 공격 호출 2회를 재생·종료한 뒤 속성별 Active 0 / Inactive 6 / All 6을 확인했다. 두 호출의 개체 ID가 같고 전체 풀 개체 36개가 유지됐다.
- 카메라 크기 7.5에서도 6개체의 기존 SlimeMotion과 Animator를 정상 속도로 재생해 이동·착지 화면을 확인했다. 속성별 임시 목표를 둔 통제된 재현이며, 실제 플레이어와의 전체 전투 검증은 아니다.
- 최종 콘솔 오류·경고는 0개다. 게임 C# 13개 해시를 작업 전과 대조했다. Play·Pause를 끄고 카메라 크기 7.5, 백그라운드 실행 false, 씬 수정 표시 없음으로 마쳤다.

확인 결과는 연결·화면 표시·재생 종료·풀 재사용에 한정한다. 18종 전체 크기의 최종 균형, 다수 개체 동시 표시의 혼잡도, 모바일 실기기 성능과 사용자의 미적 만족은 추가 확인 대상이다. 성능 개선율은 측정하지 않았다.
