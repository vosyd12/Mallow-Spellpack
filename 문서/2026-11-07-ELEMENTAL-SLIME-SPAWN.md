# 속성·크기 랜덤 생성의 Prefab 연결

수정 이력: 아래 파일 검사는 Prefab의 예약 ID 오류를 놓쳤다. 이후 슬롯 등록 불가·생성 실패가 확인돼 [예약 ID 충돌을 수정하고 Unity에서 재임포트](2026-11-07-PREFAB-RESERVED-ID-FIX.md)했다. 현재 연결과 검증 상태는 해당 후속 기록을 우선한다.

작업일: 2026-11-07. 사용자가 랜덤 추첨·Prefab 검색 코드를 작성한 뒤, 남은 Inspector·Prefab 연결을 AI에 요청했다. C# 수정 금지 조건을 유지했다.

## 문제와 원인

기존 씬의 Spawner에는 기본 슬라임 3종만 등록돼 있었다. 속성 Variant 18종은 외형이 준비돼 있었지만 `EnemyState.Size`·`Element` 값과 실제 생성 목록이 연결되지 않았다. 사용자 코드가 조합을 추첨해도 해당 값을 가진 Prefab을 찾을 수 없는 상태였다.

사용자는 `EnemyState`를 직렬화하고, `Spawn()`에서 크기·속성을 각각 추첨한 뒤 `FindEnemyPrefab()`으로 일치하는 개체를 찾도록 작성했다. 검색은 Instantiate 이전에 Prefab의 데이터를 읽으므로, 분류 값을 생성 후에만 대입하는 방식으로는 이 검색을 해결할 수 없다.

## 선택한 방법과 완료한 변경

- `Assets/Prefab/Slimes/{속성}/Slime{속성}{크기}.prefab` 18종에 `_enemy.Element`·`_enemy.Size`를 재정의했다.
- `Assets/Scenes/SampleScene.unity`의 `_enemyPrefabs`를 기존 3종에서 18종의 Enemy 참조로 교체했다. 플레이어·스테이지·부모·생성 수 설정은 유지했다.
- 씬의 `Enemy[]`가 각 Variant에 상속된 Enemy 컴포넌트를 참조하도록 연결했다. 원본 컴포넌트와 Variant의 GUID를 혼동하지 않도록 Variant 내부 참조도 명시했다.
- 크기별 원본 Prefab·이미지·Animation은 수정하지 않았다. 몸·얼굴·그림자·먼지·HP바·피격 반응 연결과 Small 확대도 유지했다.

별도 생성 스크립트나 이미지 교체 코드를 추가하지 않았다. 현재 18개 후보는 생성 시 한 번 순회하는 기존 검색으로 처리한다. 사용자가 코드 구조를 직접 이해하고 수정할 수 있도록 기존 방식에 필요한 에셋 값만 연결했다.

## 분류 값과 동작

| 분류 | 직렬화 값 |
| --- | --- |
| Small / Medium / Large | 0 / 1 / 2 |
| Fire / Water / Earth / Wind / Lightning / Pure | 0 / 1 / 2 / 3 / 4 / 5 |

실제 enum 선언 순서와 대조해 지정했다. `Max`는 후보로 등록하지 않는다. 여섯 속성마다 세 크기를 한 번씩 등록해 18개 조합에 누락·중복이 없도록 했다. 기존 무속성의 식별자는 `Pure`다.

흐름은 `크기 추첨 → 속성 추첨 → 두 값이 같은 Prefab 조회 → 생성 → 플레이어 연결`이다. 균등 추첨에 따른 의도 확률은 각 크기 1/3, 각 속성 1/6, 각 조합 1/18이다. 실제 플레이의 출현 빈도를 통계로 측정한 결과는 아니다.

Prefab은 이름에 맞는 외형을 이미 갖고 있으므로 생성 후 별도로 Sprite를 덮어쓰지 않는다. `Awake()`가 HP·MP·공격력 등은 초기화하지만 분류 값은 덮어쓰지 않는 점도 확인했다. 속성 이름을 지정한 것과 속성 전투 효과를 구현한 것은 구분한다.

## 확인 결과·남은 문제

파일 검사로 18개 조합의 전수 포함, 등록 중복·누락 여부, 씬의 Enemy 참조와 Variant 내부 컴포넌트 연결을 확인했다. 기존 Variant에서 추가된 내용은 분류 값 두 개와 Enemy 참조이며 외형 설정은 동일하다. 씬은 후보 목록만 바뀌었다. 작업 전후 해시로 C#·원본 Prefab·이미지·Animation·대상 외 에셋이 보존됐음을 확인했다. [연결 목록·확인 결과](검증자료/2026-11-07-속성슬라임스폰/CONNECTIONS.json).

Unity 임포트·Play Mode·MCP·실기기 검증은 수행하지 않았다. 실제 생성된 개체의 Size·Element와 외형·크기별 모션이 일치하는지는 실행해서 확인해야 한다. 성능 변화는 측정하지 않았다.

이미 보고한 생성 수 비교 `>`와 재시도 시각 `Time.time - 0.5f`는 코드 수정 금지 조건에 따라 유지했다. HP 0의 빠른 잔상 정리와 사망 흐름, 속성별 효과·상성·피해 계산도 남아 있다. 이번 작업의 완료 표시는 18종 랜덤 외형 선택·생성 연결 범위다.
