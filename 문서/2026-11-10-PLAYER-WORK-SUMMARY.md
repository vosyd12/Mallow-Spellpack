## 최신 코드 준비 상태

사용자가 Player·PlayerAttack·PlayerMotion에 HP 0 사망 처리, 이벤트 구독/해제, 이동/공격/피격/사망 상태 호출과 애니메이션 시점 발사 함수를 작성했다. 소스 검토에서 이전 대상 검사·사망 재귀·이벤트 호출 문제의 수정을 확인했다. PlayerMotion 부착·참조와 Attack/Hit 클립 이벤트는 남아 있어 실제 자동 재생·공격 연결은 미완료다. [원인·구조 선택·확인 결과·남은 연결](2026-11-10-PLAYER-MOTION-CODE-REVIEW.md). 아래 이전 제작·검증 기록과 구분하며, 이번에는 컴파일·Play 검증을 하지 않았다.

## 기본 행동은 5가지

애니메이션 제작과 게임 로직 연결을 별도로 판단한다. 사망은 새 포즈 원화 없이 기존 파츠 전체의 이동·회전으로 표현할 수 있다.

| 행동 | 제작·게임 연결 상태 | 확인한 내용과 남은 작업 |
| --- | --- | --- |
| **Idle** | 제작·게임 연결 완료 | 3.6초 반복 호흡·모자·양갈래·눈 깜빡임. 이전 MCP Play에서 실제 반복을 확인했다. |
| **Walk** | 클립 제작 완료, 자동 전환 미연결 | 0.98초 반복 발 교대·지지 발 보정·후행 움직임. 임시 Unity 프리뷰에서 확인했다. 실제 이동 중 속도·접지 검증은 후속 작업이다. |
| **Attack** | 단독 클립 제작 완료, 동작 보완·게임 연결 미완료 | 0.70초 클립이 있으나 작은 회전 위주라 내미는 동작의 가독성 보완이 필요하다. 실제 공격과 발사 순간 동기화는 미연결이다. |
| **피격** | 단독 클립 제작 완료, 게임 연결 미완료 | 0.42초 몸 움찔·눈·입 반응·복원. 현재 게임의 Torso 피격색과 별도이며 전체 피격 그라데이션·Bloom은 미구현이다. |
| **사망** | 클립·사망/재생 코드 준비, 에셋 연결 미완료 | 후속 수정으로 0.90초·3회전·높은 포물선 이탈. PlayerMotion 참조·실제 사망 순간 자세 포착과 게임 화면 이탈·후속 처리가 남았다. |

후속 연결에서 Controller에 **Idle·Walk·Attack·Hit·Death 상태를 등록**했다. 이후 재생 호출 코드도 준비됐으나 PlayerMotion 부착·참조·클립 이벤트는 미연결이다. Walk 제작·상태 등록·코드 작성을 자동 전환 완료로 기록하지 않는다. [상태 등록과 사망 연결 범위](2026-11-10-ANIMATION-WIRING.md)

## Bullet 발사 위치

현재 PlayerAttack은 직렬화된 _firePos를 사용하고 Instantiate의 생성 위치도 _firePos.position이다. 저장된 씬의 참조는 **Staff 자식 FirePos**로 연결되어 있다. 코드·씬 파일 대조로 확인했으며 이번 문서화에서 새 실행 검증은 하지 않았다.
- FirePos가 없으면 MagicAttack이 반환한다. 기존 사거리 판단은 Player 중심을 기준으로 한다.
- Staff의 움직임을 따라 발사 위치도 이동하는 구조다. Attack 모션과 Bullet 생성 시점을 연결할 함수는 준비됐으며 클립 발사 이벤트 등록이 남았다.
- Walk 단독 제작에서 손과 지팡이의 상대 위치는 검증했지만, 실제 이동·공격과 함께 재생하는 검증은 진행하지 않았다.

## 확정한 사망 표현

**사망 순간의 외형을 고정 → 캐릭터 전체 회전·포물선 이동 → 완전히 화면 밖으로 나간 뒤 표시 정리**를 기본 방향으로 한다. 모자·머리·몸·지팡이를 분리해 날리지 않고 한 덩어리로 다룬다.

사용자는 가벼운 느낌을 원하며 **쿠키런: 크럼블**의 사망 처리를 참고 대상으로 제시했다. 별도 움츠러듦·사망 표정·추가 강조 효과를 먼저 넣자는 이전 AI 제안은 기본 범위에서 제외한다. 레퍼런스 사망 장면의 영상 대조는 아직 하지 않았으므로 동작 세부를 실제 관찰 결과로 기록하지 않는다.

진행 방향·포물선 높이·회전 속도/횟수·시간·화면 밖 판정과 이후 게임오버/재시작은 미정이다. HP 0의 이동·공격·충돌 정리와 중복 사망 방지도 별도 연결해야 한다. 현재 Player.TakeDamage는 HP·HP바·피격색 갱신까지 처리하며 사망 전환은 없다.

## 후속 피격 효과

현재 단일 _bodyRenderer가 Torso를 가리키므로 몸통만 붉어진다. 사용자 요청은 캐릭터 전체에 피격 반응을 주고, **원본 알파를 유지하면서 효과의 혼합 알파를 중앙에서 외곽으로 높인 뒤 절제된 Bloom을 더하는 것**이다. 전용 피격 모션과는 별도 시각 효과다.

현재 카메라 후처리는 꺼져 있고 기본 Volume의 Bloom 강도는 0이다. 파츠 공통 기준·원화 가독성·효과 복원·HUD/배경 번짐을 검토해야 한다. 장비 포함 여부와 구체 강도·시간은 미정이며 실제 효과는 구현하지 않았다. [개선 항목·확인 기준](2026-11-10-PLAYER-HIT-GLOW-TODO.md)

## 확인 범위·문제와 남은 작업

이전 문제는 플레이어의 그림체·세부 밀도가 배경·슬라임과 달랐고, 단일 이미지와 불완전한 분리 경계가 동작을 제한한 것이다. 단순한 표준 원화와 파츠 관리를 선택하고, 현재는 작은 동작과 눈 뒤 피부 보완으로 Idle·Walk를 구성했다. 이후 [슬라임 새 스타일과 Death 단독 클립](2026-11-10-SLIME-STYLE-V3-APPLIED.md)을 적용했다. 배경 전체의 새 그림체 교체는 이번 작업에 포함하지 않았다.

초기 통합 문서화에서는 관련 코드·Controller·클립·씬 참조·기존 검증 기록을 읽어 상태를 대조하고 문서만 최신화했다. 그 이후 사용자 요청으로 Attack·피격·사망 클립을 별도 제작했으며 상세 범위는 위 후속 기록을 따른다. 기존 Idle Play 검증과 Walk 임시 프리뷰 결과는 당시 범위이며 전투 전체 재검증이나 재미·성능 개선의 확인 결과가 아니다.

대조한 C#·플레이어 프리팹·애니메이션·셰이더 파일은 문서화 전후 해시가 일치했다. 작업 도중 별도 씬 저장으로 초기 해시와 달라진 것은 감지했으며, FirePos·몸통 피격·후처리 참조를 다시 확인하고 해당 저장 내용은 그대로 보존했다. 위의 변경 없음은 이번 문서화에서 AI가 수정하지 않았다는 뜻이다.

기본 행동 5종의 클립이 준비됐으며, 이동/공격/피격/사망 상태와 실행 시점 연결은 남아 있다. 코드 작업은 사용자가 주도하고 AI는 필요한 수정안을 안내하며 에셋·Hierarchy 연결·허용된 실행 검증을 보조한다. 클립 제작 완료와 플레이어 기능 전체 완료를 구분한다. 아래 본문 중 기존 게임 동작·확인 기록은 작성 시점의 범위이며 새 클립의 자동 재생을 뜻하지 않는다.
