# 현재 구현·남은 문제

> 이 문서는 2026-11-06 당시 기록이다. 아래 자동 레벨업·HP바 미연결 설명은 이후 변경됐다. 현재 구현과 최신 작업 범위는 [2026-11-09 작업 요약](2026-11-09-WORK-SUMMARY.md)을 우선한다.

2026-11-06. 코드·저장된 SampleScene·Prefab·Animation을 대조했다. 문서화 과정에서는 C#과 게임 설정을 수정하지 않았다. 사용자 작성 코드와 이번까지의 UI/연출 변경을 함께 공유하는 기록이다.

## 현재 흐름

- 생성: EnemySpawner가 네 변 중 하나와 그 위의 위치를 무작위 선택한다. 맵 로컬 크기와 안쪽 여백·플레이어 안전거리를 확인하며 최대 40회 위치를 시도한다. 40마리를 만드는 반복문이 아니다. 삭제된 적은 목록에서 제거한다.
- 플레이어: 검색 타이머가 정상 감소하고 씬의 EnemySpawner가 연결돼 있다. Player.Target을 PlayerAttack이 읽고 Enemy를 대상으로 Bullet을 생성한다. 탄환은 지정 적을 추적하고 명중 시 한 번 피해를 준다. 사용자는 대화에서 공격 작동을 확인했으며 이번 점검에서 재생을 다시 검증하지 않았다.
- 적 처치: HP 0에서 추적 중인 플레이어에게 EnemyState.Exp(현재 10)를 지급하고 제거한다. HP 0 이하/비양수 피해를 거르는 조건으로 중복 보상을 방지한다. Player는 경험치를 더하고 Update에서 레벨업 필요량을 차감한다.
- 슬라임: 별도 EnemyMotion/상태 클래스 없이 SlimeMotion의 작은 enum과 시간 관리로 Idle·Prepare·Jump·Land·Attack을 제어한다. 기준 이동속도는 Enemy.MoveSpeed에서 읽는다. Animator 자동 Transition은 제거됐다.
- 공격 연출: 사거리/재사용 시간에 따라 일반 도약보다 높은 공격 도약을 하고, 공중 구간에 플레이어의 출발 당시 위치 방향으로 전진한다. 강한 먼지와 착지 후 감쇠 반동을 포함한다. 공용 먼지 풀을 재사용한다.
- HP바: 공통 World Space UI를 플레이어·슬라임 3종에 배치했다. 슬라임은 별도 HealthBarMotion 위치 곡선으로 도약 높이만 따라가며 바는 찌그러지지 않는다. Fill은 100% 고정이고 실제 HP 갱신 코드는 없다.
- 상태 데이터: PlayerState는 Level/Exp, EnemyState는 Exp를 사용한다. Element 열거형은 선언만 있으며 속성 피해 계산은 없다. Stage는 현재 빈 컴포넌트다.

## 해결된 이전 문제

타깃 타이머의 대입 오류, Player의 Spawner 참조 누락, PlayerAttack의 대상 미할당/EnemySpawner 오사용, Bullet 대상 타입 문제는 현재 코드에서 해결됐다. SlimeMotion GUID와 프리팹 Animator 연결도 복구됐다. 과거 문서의 같은 결함을 현재 미해결로 읽지 않는다.

## 남은 문제와 다음 수정 지점

1. **생성 규칙 불일치:** 합의는 우선 1마리 유지다. 현재 씬 `_stageSpawnerEnemyCount`는 4이며 조건은 `Count > 제한값`이라 정상 생성이 계속되면 5마리에서 멈춘다. 다음 코드 작업에서 목표 동시 수를 확정값에 맞추고 `>=` 경계로 제한해야 한다. 현재 값 4를 새로운 확정 규칙으로 해석하지 않는다.
2. **재시도 시각:** `_nextSpawnAttemptTime = Time.time - 0.5f`이므로 미래의 대기 시각이 되지 않는다. 현재는 조건이 허용하는 매 Update에서 생성 시도를 한다. 의도한 0.5초 재시도라면 `+`로 바꿀 작업이 남았다.
3. **공격 피해 호출:** `TryHitPlayer()`는 범위 확인 후 Player.TakeDamage를 호출하도록 작성됐지만 함수 자체를 부르는 곳이 없다. 공격의 첫 착지에서 한 번 호출하는 연결이 남았다.
4. **플레이어 시작 체력:** 저장된 씬의 `_maxHP`, `_maxMP`는 모두 0이다. Awake가 이를 현재 체력에 복사하므로 저장 상태 기준 시작 HP도 0이다. 실제 수치는 사용자가 설정해야 한다. HP 로그의 `_player.HP / _maxHP`는 분수 표시가 아닌 정수 나눗셈이므로 표시 방식도 수정 대상이다.
5. **사망 처리:** Player.TakeDamage의 체력 감소는 있으나 이동·공격 중지, 게임오버·재시작은 없다.
6. **HP바:** 현재/최대 HP에 따른 Fill 갱신은 사용자 코드 작업으로 남겼다. UI가 가득 차 보이는 것은 실제 체력이 가득 찼다는 뜻이 아니다.
7. **회피 경계:** 시작·종료 여유 거리용 플래그가 추가됐지만, 별도의 안전거리 반환이 여전히 남아 완전한 히스테리시스는 아니다. 종료 구간에서의 원형 이동과 접근 보정 정책을 함께 정리해야 한다.
8. **기존 적 이동:** Enemy에도 기본 이동 코드가 남아 있다. 현재 슬라임 Prefab의 Use Default Movement는 꺼져 있어 중복 이동은 피하지만, 켜거나 새 Prefab을 만들 때 주의해야 한다.
9. **화면/배치:** 세로 화면 자동 카메라 대응, 생성 시 다른 적/벽과의 실제 Collider 겹침 검사, 모바일 성능은 미확인이다.

## 작업 경위와 검증

- 사용자 요청에 따라 코드 작업은 사용자 주도이며 AI는 검토와 명시적으로 요청한 수정만 보조한다. 공격 연출 작업 때 AI가 이동/진입 코드까지 수정했던 범위는 대화에서 문제를 확인했으며, 이후 HP바 작업은 C# 변경 없이 에셋만 구성했다.
- HP바·회피·공격 연출의 원인/선택/변경/정적 검사 기록은 각 날짜별 문서를 보존했다. 해당 문서의 과거 빌드·실측 결과를 현재 파일의 실행 결과로 확대하지 않는다.
- 이번 .NET 빌드 점검은 로컬 `Temp/obj/Assembly-CSharp/project.assets.json` 누락으로 NETSDK1004가 발생해 현재 소스 컴파일 성공을 확인하지 못했다. 로컬 소스 복원도 시도했으나 해당 캐시가 생성되지 않았다. 코드 오류라고 확정할 근거는 아니며 Unity의 재생·빌드 확인이 필요하다.
- MCP·Notion·Play Mode·새 성능 측정은 사용하지 않았다. 현재 파일 지문은 [CURRENT-SOURCE.json](2026-11-06-CURRENT-SOURCE.json), 구현 체크리스트는 [MILESTONES](../MILESTONES.md)를 따른다.
