# 시스템 우선 작업과 연출 후속 과제

현재 작업의 우선순위를 미구현 시스템 완성으로 바꾼다. 시각 요소는 발동, 피격, 현재 상태를 확인할 수 있는 정도로 먼저 제공한다. 동작을 실제 게임에서 확인한 뒤 외형·색·모션을 다듬어 반복 작업을 줄인다.

| 과제 | 현재 상태와 다음 작업 |
| --- | --- |
| 피격 시 체력바 표시 | `HealthBar.cs`는 공통 체력 비율과 피해 잔상을 처리한다. `Player.TakeDamage()`와 `Enemy.TakeDamage()`가 HP를 갱신하고 사망 시 `Hide()`를 호출한다. 두 캐릭터의 머리 위 바를 평소 숨기고 실제 HP 감소 시에만 잠시 표시하는 규칙이 필요하다. 초기화·부활·회복에는 HP 값을 갱신하고, 표시 여부는 별도로 관리한다. 연속 피격 시 표시 시간을 연장하는 방식과 유지 시간은 검토한다. 상단 HUD와 보스 게이지는 별도 표시다. |
| 플레이어·Enemy 자동 전투 | 플레이어의 대상 선택·회피 거리와 적의 추적·도약·공격 전환이 이미 있다. 먼저 대상 전환, 거리 경계, 장애물 근처에서 왜 움직임이 어색한지 확인하고 필요한 이동·판단 규칙을 개선한다. 구체 알고리즘은 검토 중이다. |
| 번개 속성 스킬 | `Element.Lightning`과 번개 슬라임이 있다. 플레이어 스킬의 발동, 대상·피해 판정, 쿨다운, 슬롯 표시를 연결할 과제로 등록했다. 번개 공격의 형태·대상 수·사거리는 검토 중이다. |
| 스테이지 중앙 타이틀 | `StageInfo.SetInfo()`는 HUD에 스테이지 번호를 표시한다. 기존 보스 타이틀의 프리팹 구조·글꼴·배너·클립을 재사용할 수 있다. 중앙에서 실제 스테이지 번호를 보여주려면 `Stage.EnterStage()`에서 번호와 재생 신호를 한 번 전달하고 `StageInfo`에서 텍스트를 설정한다. `EnterStage()`는 첫 시작·다음 스테이지·같은 스테이지 재시작에 모두 호출되므로 어느 경우에 재생할지 먼저 결정한다. |
| 체력바 외형과 키프레임 | 프로젝트에 맞는 외형을 공통 체력바 Prefab에서 구성한다. CanvasGroup 투명도나 크기 키프레임으로 등장·퇴장을 다듬고, 실제 HP 비율은 기존 체력 계산으로 갱신한다. 표시 로직을 먼저 검증한다. |
| 플레이어·Enemy 외형과 모션 재작업 | 현재 플레이어 리그와 슬라임 파츠·모션을 기준으로 전체 외형과 움직임을 재검토한다. 이동과 전투 판단이 정리된 뒤 대기·이동·공격·피격·사망 모션을 새로 잡는다. 작업 시 `AGENTS.md`의 기준 Prefab·GUID·클립·리깅 보존 및 참조 검증 규칙을 따른다. |

## 다음 작업 인수인계

- **결정** — **확정** 시스템과 기본 시각 표시를 먼저 완성한다. 플레이어·Enemy 머리 위 체력바는 피격 때만 표시하고 번개 플레이어 스킬을 추가한다. **검토 중** 체력바 표시 시간·연속 피격 처리, AI 개선 방식, 번개 스킬 형태, 스테이지 타이틀 재생 시점. **보류** 체력바 외형·키프레임의 세부 조정과 캐릭터 외형·모션의 전체 재작업.
- **적용** — 요구사항과 현재 구현 상태를 `MILESTONES.md`에 등록했다. 이번에는 문서를 갱신했다.
- **검증** — 현재 `Stage`, `StageInfo`, `HealthBar`, `Player`, `Enemy`, `SlimeMotion`, `EnemySpawner`, `PlayerSkill`의 관련 코드를 대조했다. 이번에 등록한 기능의 Unity 실행 검증은 구현 후 진행한다.
- **다음 작업** — 작업 순서 제안은 공통 피격 체력바의 표시 규칙부터 연결하고, 번개 스킬과 자동 전투를 기본 표시로 검증하는 것이다. 체력바 모션과 캐릭터 외형은 해당 동작이 정해진 뒤 다듬는다.
- **공유 기준** — 마지막 문서에 기록된 원격 `main` 기준은 `259aba2`다. 현재 작업 폴더에서 원격 최신 상태를 확인하지 못했다. 이번 작업 순서와 요구사항 문서 변경은 현재 폴더에 저장했다.
