# 프로젝트 작업 현황과 후속 과제

기준일: 2026-11-09. 지금까지의 코드·씬 연결·외형·UI 시안·개선 논의를 모은 재개용 문서다. 개별 작업의 상세 기록은 아래 링크를 따른다. 이번 문서화는 로컬 파일 대조이며 MCP 실행·Notion 조회·신규 기능 적용·Git 업로드는 하지 않았다.

## 현재 구현된 흐름

`Stage 진입·배경 배치 → 적 생성 → 타깃 탐색·자동 공격 → 피격·HP 갱신 → 적 처치·경험치 획득 → 조건 충족 시 버튼으로 한 단계 레벨업`

- 플레이어는 가까운 적을 탐색하고 거리·공격 주기에 따라 추적 탄환을 발사한다. 가까운 적에 대한 회피가 있으며 경계 조건 정리는 남아 있다.
- 적은 플레이어를 추적하고 일반·공격 도약을 한다. 피격 색상 반응과 실제 HP/노란 피해 잔상을 표시한다. 적 처치 시 경험치를 지급하고 즉시 제거한다.
- 슬라임은 6속성 × 3크기 Variant 18종을 생성 목록에 연결했다. 몸·얼굴·장식이 분리돼 있고 속성별 착지 효과는 공용 풀에서 재사용한다. 추가 속성 피해·상성은 미구현이다.
- 플레이어 HP 감소는 연결됐으나 HP 0 이후 이동·공격 종료와 게임오버·재시작은 미완료다.

현재 코드 근거: [Player](../Assets/Scripts/Player/Player.cs), [PlayerAttack](../Assets/Scripts/Player/PlayerAttack.cs), [Bullet](../Assets/Scripts/Bullet.cs), [Enemy](../Assets/Scripts/Enemy/Enemy.cs), [SlimeMotion](../Assets/Scripts/Enemy/SlimeMotion.cs), [HealthBar](../Assets/Scripts/UI/HealthBar.cs). 구현 체크는 [MILESTONES](../MILESTONES.md)를 따른다.

## Player·Stage·UI의 현재 역할

- **Player:** 경험치·레벨·다음 필요량을 관리하고 PlayerInfo에 표시값을 전달한다. GainExperience는 경험치만 더하며 자동 레벨업하지 않는다. TryLevelUp은 조건 충족 시 한 번에 한 레벨만 올리고 초과 경험치를 남긴다. 현재 레벨업에 스탯 상승은 없다.
- **PlayerInfo:** 이름·레벨·현재/필요 경험치·게이지와 레벨업 버튼 활성 상태를 표시한다. 씬 버튼은 Player.TryLevelUp에 연결돼 있다.
- **Stage:** 스테이지 번호와 보스 진행도를 관리하고 StageScenery.Rebuild·StageInfo 갱신을 호출한다. 진행도 자동 증가 조건과 보스 생성은 없다.
- **StageInfo:** Stage 번호·보스 Fill·가득 찼을 때 등장 안내를 표시한다. 골드 Image/Text 필드는 있으나 금액 전달·갱신 로직과 씬 연결이 없어 현재 HUD에서 제외했다.

코드는 사용자가 주도했다. AI의 최근 HUD 작업은 씬·Inspector·에셋 연결이며 C# 소스 파일은 변경하지 않았다. 단, MCP에서 임시 C# 명령을 실행해 Unity 설정을 조정했으므로 이를 코드 실행 자체가 없었다는 뜻으로 사용하지 않는다.

## 문서화만 완료한 개선 과제

### 기존 슬라임·Stage·성능 요청

머리 위 속성 표시 제거, 눈·입 표정 변화, 화면 밖으로 날아가는 사망, 작은 착지 입자 제거, 접촉감 보강, 대형 얼굴 위치 보정, 세 가닥 풀숲 확대, FPS·CPU·오브젝트 관리 진단의 8개 요청은 [기존 과제 문서](2026-11-09-PRESENTATION-AND-PERFORMANCE-TODO.md)를 따른다.

해당 문서화 중 잘못 적용했던 연출 변경은 원복했다. 표정·사망·풀숲 변경을 완료로 보고하지 않으며 앞서 승인한 가림과 StageScenery 연결은 유지한다. FPS 저하 원인은 미확정이고, 착지 효과는 이미 풀링을 사용한다.

### UI·연출·기본 재미 검토

[후속 검토 문서](2026-11-09-UI-AND-GAME-FEEL-REVIEW.md)에 폰트·이미지의 외곽선·명암·색상·선명도 통일, HUD 개성과 시선 구성, 짧은 등장 연출, 명중·처치·성장 반응을 정리했다. 화면의 시각적 호감과 반복 전투를 관찰하는 재미는 별도로 평가한다.

권장 순서는 시각 기준 선정 → 대표 HUD 비교 → 기존 행동의 작은 범위 개선 → 같은 조건에서 전후 평가다. 스타일·시간·강도는 미정이며 재미 향상·성능 개선도 아직 검증하지 않았다. 전투 중 겹침은 이 후속 검토에서 제외한다.

## 확인된 문제와 검증 한계

- HUD 시험 중 비활성화했던 PlayerAttack·EnemySpawner가 에디터에 남아 전투가 멈췄던 문제는 복구했다. 이후 일반 전투·EXP 갱신을 재확인했다. 재발 방지를 위해 시험용 상태 변경과 원복 여부를 확인한다.
- 기존 생성 제한 경계·재시도 시각, 회피 경계, HP 0 이후 처리, 보스 자동 진행은 남은 코드 과제다. 이번 문서화에서 고치지 않았다.
- 한글 HUD 폰트는 제한된 글자만 포함하므로 새로운 캐릭터명·문구에 대한 지원은 별도 확인이 필요하다.
- 과거 포인터 클릭 처리는 실제 물리 마우스 입력 검증과 다르다. 당시 콘솔·화면 확인도 모바일 빌드·장기 안정성·전체 전투 검증을 뜻하지 않는다.
- 오래된 구현 문서의 자동 레벨업·HP바 미연결 설명은 해당 작성 시점의 기록이다. 최신 상태는 이 문서와 현재 코드·개별 최신 변경 기록을 우선한다. Git 공유 문서 역시 과거 시점이며 이번 업로드 완료를 의미하지 않는다.

## 작업 재개 기준

1. [AGENTS](../AGENTS.md)를 읽고 적용 작업과 검토 제안을 구분한다. 사용자가 코드를 주도하며, 문서화 요청으로 실제 기능을 추가하지 않는다.
2. MCP는 해당 작업에서 사용자가 허용한 범위 안에서 사용한다. 이전 연결 허용을 모든 후속 요청의 허용으로 확대하지 않는다. Notion은 요청 시에만 사용한다.
3. 필요한 변경만 작은 범위로 진행하고 확인·원복·CHANGELOG 기록을 남긴다. 기능이 바뀌면 구현 상태와 기대 효과·실제 결과를 구분해 문서를 갱신한다.

이번 변경은 이 요약과 관련 문서 안내·오래된 현황 설명·이력의 최신화다. 게임 파일을 변경하거나 새 개선안을 구현하지 않았다.

## 후속 GitHub 공유 범위와 전송 방식

사용자의 커밋·업로드 요청에 따라 기존 `vosyd12/Mallow-Spellpack`의 main 이력을 부모로 현재 작업을 공유한다. 위 문서화 작업과 별도의 후속 작업이며, 과거 공유 기록을 이번 업로드 결과로 간주하지 않는다.

- 문제·원인: 현재 작업 폴더에는 `.git`이 없고 명령줄 GitHub 접속도 실패했다. 연결된 GitHub 도구에서는 기존 저장소와 main 접근·쓰기 권한을 확인했다.
- 선택: GitHub Git Data API로 기존 main 위에 후속 커밋을 만든다. 기존 이력을 강제 덮어쓰거나 작업 폴더에 없는 원격 파일을 삭제하지 않는다.
- LFS: 연결 도구에 LFS 업로드 기능이 없어, 이번에 새로 추가한 이미지·폰트 21개(합계 약 16.2 MiB)는 일반 Git blob으로 저장하도록 `.gitattributes`에 해당 경로만 예외를 추가한다. 기존 이미지의 내용은 LFS 포인터 해시로 대조해 불필요한 재업로드·저장 방식 변경을 피한다. 기존 LFS 객체와 규칙은 유지한다.
- 포함: 사용자 작성 코드 변경, Prefab·씬·UI·TMP 리소스와 `.meta`, 프로젝트 설정, 최신 시안·검증 자료·문서다. 업로드를 위해 C# 내용을 수정하지 않는다.
- 제외: Library·Logs·UserSettings·IDE 캐시·Temp와 ProfilerCaptures다. 프로파일러 캡처 폴더는 `.gitignore`에도 명시한다.
- 완료 확인 기준: 원격 main이 새 커밋을 가리키고, 업로드 blob 해시와 변경 경로가 준비한 파일과 일치해야 한다. 실제 커밋 식별자와 원격 반영 결과는 최종 완료 응답에서 확인한다. 이 작업이 Unity 새 빌드·전투 재검증을 뜻하지 않는다.
