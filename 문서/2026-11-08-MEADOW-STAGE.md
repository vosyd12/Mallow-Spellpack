# 초원 Tilemap과 나무 배치

작성일: 2026-11-08. 상태: Stage Prefab 적용·MCP 화면 확인 완료. 게임 C#·전투·착지 효과·UI 코드는 수정하지 않았다.

## 요청과 선택 이유

사용자는 현재 연출이 주변 화면과 어울리지 않는다고 느꼈고, 임시 격자 바닥을 초원과 간단한 나무가 있는 맵으로 변경하도록 요청했다. 이후 쿠키런: 크럼블을 바닥·오브젝트·이펙트와 향후 화면·UI 구성의 주요 참고로 지정했다. 기본 시각 배치를 갖춘 뒤 독자 규칙을 더하는 방향이다.

기존 Stage는 실제 Tilemap이 아니라 80개의 사각 Sprite와 테두리·배경이었다. 이를 Unity 기본 Grid·Tilemap으로 바꾸면 바닥을 타일 데이터로 직접 편집할 수 있다. 나무는 반복 사용 가능한 Prefab으로 분리하고 중앙 전투 공간을 비웠다. 실제 이동 경계와 카메라를 보존해 맵 외형 수정이 생성·이동에 영향을 주지 않도록 했다.

## 적용한 구성

```text
Stage (기존 배율 1.5 유지)
├ Bounds (기존 벽 4개 유지)
├ MeadowGrid
│ └ Grass (Tilemap + TilemapRenderer)
└ Scenery
  └ Tree01 … Tree14 (나무 Prefab 인스턴스)
```

- 잔디 Tile 1종을 224칸에 배치했다. 기존 이동 영역의 80칸과 바깥 배경을 함께 그린다. 한 칸은 로컬 0.75, 월드 1.125다.
- 실제 이동 영역은 기존 월드 X ±4.5 / Y ±5.625다. 바깥 잔디가 보여도 이동 범위는 확장되지 않는다.
- 나무 2종은 외곽에 14개 배치했다. 충돌체를 추가하지 않았다. 바닥 -100 → 나무 그림자 -25 → 나무 -20 → 기존 캐릭터 순서로 그려 배경 나무가 캐릭터 위를 덮지 않도록 했다.
- 나무 밑에 기존 `GroundShadowMask`를 재사용해 낮은 불투명도의 타원 그림자를 넣었다. 실시간 조명·블룸·바람 애니메이션은 추가하지 않았다.
- 기존 체크무늬 Row·Border·Backdrop은 현재 Stage에서 제거했다. 작업 전 Prefab은 `.utmp/MeadowStage-20261108/before`에 보관했다.

| 편집할 내용 | 위치 |
| --- | --- |
| 전체 맵 | `Assets/Prefab/Stage.prefab` |

## 쿠키런 크럼블 공개 자료에서 관찰한 점

자료: [공식 소개](https://cookieruncrumble.com/ko), [개발사 Google Play 스크린샷](https://play.google.com/store/apps/details?hl=ko&id=com.devsisters.cc). 홍보 이미지의 실제 게임 화면 부분을 중심으로 확인했다. 이번 확인은 정지 이미지 기반이며 영상의 프레임별 타이밍 분석은 아니다.

| 관찰한 화면 특징 | 우리 프로젝트에서 참고할 방향 |
| --- | --- |
| 바닥의 길·반복 패턴은 캐릭터 외곽선과 전투 효과보다 대비가 낮다. | 바닥은 공간을 설명하고 전투 대상의 식별을 방해하지 않도록 한다. |
| 부유한 개체 아래에도 타원형 그림자가 보여 바닥과의 관계를 알 수 있다. | 발밑 기준과 그림자를 먼저 맞추고 부가 광원을 검토한다. |
| 청색 효과는 밝은 중심과 바깥쪽 색 면·곡선 형태가 구분된다. | 발광 세기만 높이기 전에 본체 형태·밝은 부분·바깥 색을 설계한다. |
| 발밑 원형 표시와 몸체가 별도 층처럼 보인다. | 바닥에 놓이는 표시와 공중 효과를 역할별로 나눠 읽히게 한다. 원형 표시의 게임상 용도는 이 자료만으로 단정하지 않는다. |
| 배경 구조물은 멀리서 약하게 보이고 전투 개체는 선명한 외곽을 갖는다. | 배경과 캐릭터의 대비를 구별한다. |
| 상단 진행 정보, 측면 버튼, 하단 성장·캐릭터 영역이 구분된다. | 추후 UI 배치 검토 시 참고한다. 이번 UI 변경은 없다. |

내부 Sprite·메시·셰이더·파티클·블룸 설정, 실제 아틀라스 구성과 성능 최적화 방법은 공개 스크린샷에서 확인할 수 없다. 위 표는 시각적 관찰과 우리 구현에 대한 적용 방향이며, 원작 기술을 확인했다는 뜻이 아니다. 화면 전체의 화려함을 통째로 가져오기보다 필요한 역할부터 조합한다. 참고 이미지는 학습 자료로만 보관하고 게임 에셋에는 사용하지 않았다.

## 확인한 결과와 남은 범위

- MCP에서 Stage Prefab·씬 연결을 조회하고 실제 카메라 화면으로 수정 전후를 확인했다.
- Play Mode에서 기존 Spawner의 적 생성·SlimeMotion 활성화와 맵 표시를 확인했다. 별도 통제 배치에서는 6속성 Medium의 착지 효과를 초원 위에서 확인했다. 전체 전투의 회귀 검증은 아니다.
- 기존 벽 4개의 위치·크기·오프셋과 Stage 배율·카메라 크기 7.5를 작업 전과 대조했다. 배경 나무의 충돌체는 0개다.
- 게임 C# 13개와 씬 파일의 해시를 전후 대조했다. 마지막에 Play·Pause를 끄고 백그라운드 실행 false, 씬 수정 표시 없음으로 복원했다. 최종 콘솔 오류·경고는 0개다.
- Tilemap으로 교체했지만 GPU·CPU·메모리의 성능 개선율은 측정하지 않았다. 초광폭 화면 자동 대응, 모든 화면 비율·모바일 실기기, 18종 전체와 다수 전투의 가독성은 이번 확인 범위가 아니다.
- 나무 크기·간격·잔디 색의 최종 미적 판단은 사용자 피드백으로 보완한다. 현재 바깥 배경과 실제 이동 경계 사이의 구분은 나무 배치로 암시하며, 필요하면 이후 경계 표현을 검토한다.
