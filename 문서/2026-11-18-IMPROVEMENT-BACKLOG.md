## 문제의 원인과 후속 접근

### 상단 Area와 화면 기준

`IngameScene.unity`의 현재 HUD는 `1080×1920 / Match 0.5 / Overlay`다. 상단 Area에는 다음 값이 저장되어 있다.

| Area | Anchored Position | Size Delta |
| --- | --- | --- |
| PlayerInfoArea | (-110.71954, 0) | (-221.4391, 180) |
| StageInfoArea | (-160.91382, 0) | (-321.8276, 180) |

앵커 공간에 음수 폭·위치 보정이 더해져 최초 검증 때의 32%/68% 영역 분배와 달라졌다. 저장값과 과거 화면 이탈 기록으로 재점검 대상으로 분류한다. 음수 오프셋 자체를 항상 오류라고 판단하거나 이번에 0으로 바꾸지는 않는다. 후속 작업에서는 Area 배치와 Panel 종횡비를 나눠 확인하는 방식이 원인 구분에 적합하다.

이전 대화의 1920×1080·16:9 기준 동일 배율/여백 요구와 현재 문서의 독립 월드·반응형 모바일 HUD 기준은 다르다. 적용할 화면 정책을 확인하기 전에는 현재 배치를 과거 기준으로 일괄 복원하거나 전체 대응 완료로 판정하지 않는다. 물리·충돌·이동을 가진 Transform의 배율을 일괄 변경하지 않고 기존 참조를 보존한다는 제약은 유지한다.

Safe Area는 화면 배율과 별개로 다룬다. 고정 비율 여백만으로 모든 노치 대응을 완료할 수 없으므로, 후속 구현에서 기기 안전 영역을 기준으로 정보 UI를 배치하는 방향을 검토한다. 구체적인 코드와 여백은 아직 확정하지 않았다.

### 스킬·연출의 기록 불일치

11월 17일 저장 문서에는 **물 Ball·불 장판 실험**이 기재되어 있고, 앞선 대화에는 **수동 Fireball·쿨다운 UI·레벨업 효과 연결 완료 보고**가 있다. 이 요청을 처음 정리했을 때는 빈 슬롯·스킬 코드 초안 상태였다. 다른 사본이었는지 원복된 결과인지는 확인되지 않았다.

우선 현재 작업에 사용할 사본과 스킬 방향을 확인하고 코드·Prefab·씬 참조를 함께 맞춰야 한다. 스킬 데이터 항목이나 비활성 표시 자리의 존재를 실제 장착·발동·쿨다운 구현으로 보지 않는다. VFX와 피해 판정을 분리하는 것은 구현 제안이며 새 확정 규칙은 아니다.

## 요청과 구분한 점검 항목

- 이전 검증 문서에는 Play 종료 시 `PlayerMotion.OnDisable → StopAttackMotion`의 비활성 Animator 경고가 남아 있다. 이는 기존 검증에서 발견한 보완 항목이며 사용자가 새로 지정한 UI 수정과 구분한다.
- 커밋·업로드 요청은 게임 기능과 별도의 미완료 작업이다. 현재 폴더에 `.git`이 없고 이전 업로드 시도는 완료되지 않았다. 이번 문서화에서는 GitHub 연결이나 업로드를 수행하지 않는다.
- SkillData.cs의 외부 클래스 이름은 SkillDatta다. 파일/클래스 명칭 정리는 코드 검토 항목이며 이번에 이름을 바꾸지 않는다.

## 이번 문서화의 변경·확인 범위

흩어진 대화 요청과 저장 문서의 완료 상태가 달라 중복 구현·누락 가능성이 있었다. 요청 목록을 한곳에 모으고 **현재 구현·미정·이월·기록 불일치**를 구분했다. 관련 마일스톤·문서 안내·변경 이력에서 이 목록을 찾을 수 있게 연결한다. 기대 효과는 다음 작업 범위를 명확히 하는 것이며 기능 개선 결과는 아니다.

코드·씬·Prefab 대조로 위 상태를 확인했으며 게임 코드·에셋은 수정하지 않았다. 이번에는 MCP·Notion·Unity 재생·빌드·실기기 검증을 수행하지 않았다. 과거의 Game View/Simulator 결과는 해당 작업 당시 결과로만 유지한다.
