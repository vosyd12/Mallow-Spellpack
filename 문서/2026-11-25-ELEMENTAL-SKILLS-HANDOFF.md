# 신규 속성 스킬 4종과 5스테이지 인수인계

기존 초원과 왕관 슬라임으로 Stage 1~5를 검증한다. 직접 이동과 자동 공격을 유지하고, 판 안에서 고른 마법이 회피·자리 잡기·적 무리 처리에 어떤 차이를 만드는지 확인한다. 수동 조작과 기존 성장 시스템의 변경 이력은 [수동 조작 인수인계](2026-11-24-MANUAL-COMBAT-AND-DUNGEON-HANDOFF.md)와 [뱀서류 전환 인수인계](2026-11-25-SURVIVORS-HANDOFF.md)에 있다.

## 대화에서 정한 방향

- **확정** — 첫 검증 범위는 기존 Stage 1~5다. 경험치가 차면 카드가 자동으로 열리고 선택 확정 연출이 끝날 때까지 전투를 멈춘다. 이번에는 번개 연쇄, 바람 돌풍, 땅 보호막, 무속성 이동 흔적의 네 가지 판정부터 구현했다. 대형 확장에 앞서 이 마법들이 서로 다른 움직임을 유도하는지 확인한다.
- **확정** — 연출은 Unity 에디터에서 먼저 구성한다. Prefab과 Inspector에서 배치·크기·색을 조정하고 Animator·Animation Clip·Shuriken Particle System에서 재생을 편집한다. C#은 발동·대상·피해·물리 이동·수명과 연출 시작·종료에 필요한 값만 맡는다. 사용자가 C#을 작성하고 AI는 코드 검토와 요청받은 에디터 설정을 맡는다. 기존 `Assets/Prefab/FireArea.prefab`과 `Assets/Animations/Effects/FireAreaVortex.controller`를 참고한다.
- **검토 중** — 물·불을 시작 스킬로 두고 신규 스킬을 첫 카드에서 Lv.1로 획득하는 방식으로 먼저 시험한다. 보유 스킬은 이후 카드에서 강화한다. 카드 표시 최대 3장과 보유 스킬 상한은 별도로 결정한다. 보유 상한, 후보 확률, 모바일 HUD의 최종 배치, 도전 종료·정산과 판 안팎 초기화 규칙은 사용자 판단을 기다린다.
- **보류** — 워터볼·화염 장판의 행동 특성, 정식 스킬 트리·환생, 전투력 표시·별도 던전과 5스테이지 이후 확장은 신규 스킬과 Stage 1~5를 시험한 뒤 우선순위를 다시 정한다.

## 현재 구현과 남은 검증

| 범위 | 현재 작업 폴더에서 확인한 내용 |
| --- | --- |
| 전투·진행 | 기존 보스 게이지와 왕관 보스, 2초 등장 카메라, 15초 보스 타이머를 사용한다. 현재 사망과 보스 타임아웃에는 같은 스테이지 재시작을 사용한다. 타임아웃 시 살아 있는 플레이어의 HP가 유지되는 동작은 이전 Play Mode에서 확인했다. Stage 5 종료 규칙은 남아 있다. |
| 입력·카메라·HUD | `Assets/Scenes/IngameScene.unity`의 오른쪽 아래 터치 영역에 `FloatingJoystick`이 있고 WASD·방향키와 같은 이동 액션을 사용한다. 메인 카메라는 플레이어를 추적하고 직교 크기는 5다. 상단 진행 바, 레벨 아래 물·불 쿨타임 슬롯, 카드 Animator의 `Unscaled Time`을 씬에서 확인했다. 스탯창의 골드 표시 참조는 연결돼 있고, 이전에 임시 배치했던 상단 골드 HUD의 `StageInfo` 참조는 현재 비어 있다. |
| 기존 카드 | 물·불 카드 강화와 선택 중 전투 정지가 연결돼 있다. 이전 Play Mode에서 선택 확정 후 시간 복원·보스 등장·Stage 2 진입과 두 스킬 최대 레벨일 때 EXP 보존을 확인했다. 현재 `PlayerSkill`의 자동 발동과 `LevelUpCardPanel` 후보는 물·불에 고정돼 있다. |
| 신규 스킬 기반 | `SkillBehaviour.Data`와 `TryCast()`, `SkillShape.Shield`, `EnemySpawner.SpawnedEnemies`를 반영했다. 번개와 흔적 스크립트의 파일명·클래스명을 맞추면서 기존 `.meta` GUID를 유지했다. 신규 4종과 흔적 스크립트는 저장소 작업 폴더에 있으며, 씬·프리팹에서 해당 컴포넌트 참조를 찾지 못했다. |
| 보호막·넉백 수정 | `Player.TakeDamage()`가 HP 차감 전에 보호막을 소모하고 반환한다. 치명타에서도 같은 순서를 사용한다. `Die()`의 명시적 보호막 초기화는 보완 항목이다. `SlimeMotion.FixedUpdate()`는 도약·공격의 이동량과 넉백을 합쳐 한 물리 프레임에 한 번 처리하고, 비활성화 때 남은 넉백 시간을 초기화한다. |

문서 정리 시 현재 소스로 Unity 6000.5.10f1의 C# 컴파일러를 실행해 `Assembly-CSharp`가 통과하는 것을 확인했다. 위 Play Mode 결과는 기존 기능의 이전 검증이다. 신규 4종의 씬 연결·실제 발동·최신 세로 HUD 통합 재생·실기기 검증은 남아 있다.

| 스킬 | 현재 판정과 기본값 | 에디터에서 구성할 연출과 확인 기준 |
| --- | --- | --- |
| 번개 `LightningChainSkill.cs` | 사거리 6 안의 가장 가까운 적부터 시작해 직전 대상 반경 2.5에서 다음 대상을 찾는다. 첫 타격 포함 최대 3마리, 기본 피해 15, 쿨다운 4초다. 같은 시전에서 같은 적을 한 번만 맞힌다. | 실제 타격 순서와 월드 위치를 번개 프리팹에 넘긴다. 두 적 사이의 선·색·잔광은 프리팹에서 조정한다. 사거리 밖에서 발동을 기다리고, 첫 적이 사망해도 그 타격 위치에서 연쇄되는지 확인한다. |
| 바람 `WindPulseSkill.cs` | 반경 2에서 일반 슬라임을 바깥으로 밀어낸다. 레벨당 반경 +0.2, 넉백 속도 8, 유지 0.18초, 쿨다운 6초다. 돌풍 자체의 피해는 없으며 보스는 넉백 대상에서 제외한다. | 시전 위치와 실제 반경을 충격파 프리팹에 전달한다. 일반 적이 대기·준비·도약 중 밀려나는지, 보스만 있는 경우 발동 성공으로 처리되지 않는지 확인한다. |
| 땅 `EarthShieldSkill.cs` | 피해 한 번을 막는다. 기본 2초 유지, 레벨당 +0.5초, 쿨다운 8초다. 적 유무와 관계없이 부여할 수 있고 유효한 보호막에는 재부여가 실패한다. | 보호막 생성·소모·만료에 맞춰 프리팹의 시작·종료를 재생한다. 첫 유효 피해와 치명타 차단, 두 번째 피격의 HP 차감, 시간 만료와 사망 후 외형 정리를 확인한다. |
| 무속성 `PureTrailSkill.cs`, `PureTrailMark.cs` | 이동 입력으로 발동을 검사하고 실제 이동 경로에 3초 동안 0.8유닛 간격으로 흔적을 놓는다. 흔적당 수명 2초, 반경 0.5, 기본 피해 12, 쿨다운 7초다. 범위에 적이 들어오면 같은 적의 여러 콜라이더를 한 대상으로 처리하고 흔적을 제거한다. | 흔적 프리팹 루트에 `PureTrailMark`를 붙여 `_markPrefab`에 지정한다. 타격 위치에서 별도 폭발 연출을 재생해 흔적이 제거돼도 효과가 끝까지 보이도록 한다. 정지 시 추가 생성이 없고, 흔적의 1회 피해·시간 만료·재시작 정리를 확인한다. |

## 단계별 진행 기준

[M1~M5 마일스톤](../MILESTONES.md#2026-11-25-신규-속성-스킬과-5스테이지-마일스톤)을 기준으로 진행한다. M1에서 이번 코드와 기존 전투의 실행 기준을 확인하고, M2에서 번개 한 종으로 카드 획득 → 자동 발동 → HUD 표시를 연결한다. 이후 바람·땅·무속성 등록과 스킬별 검증, Unity 연출과 세로 화면 검증, Stage 1~5 전체 검증 순으로 넘어간다. 각 단계에서 씬, Play Mode 또는 실기기 여부, 재현 조건과 결과를 남긴다.

## 다른 PC에서 이어서 작업

1. 저장소의 `main`에서 이 인수인계 문서와 신규 스킬 코드를 함께 내려받는다. 가져온 커밋과 작업 폴더 상태를 `git rev-parse HEAD`, `git status --short`로 확인한다. 이번 공유에 앞서 확인한 원격 기준은 뱀서류 전투·HUD를 반영한 `caebc2f`다.
2. 같은 상태를 재현하려면 현재 변경이 포함된 커밋을 받아오거나, 동일 기준 커밋 위에 현재 작업본을 함께 옮긴다. 저장소를 내려받을 때 Git LFS 원본은 `git lfs pull`로 준비한다. 직접 옮길 때는 `Assets/Scenes/IngameScene.unity`, `Assets/Prefab/Slimes/StageBossSlime.prefab`, 왕관 셰이더와 보스 스프라이트 임포트 설정, `Assets/Scripts/`의 변경·추가 파일과 `.meta`, 루트 문서와 `문서/`를 함께 가져온다. `Assets/`, `Packages/`, `ProjectSettings/`의 상대 경로를 유지한다. `Library/`, `Temp/`, `Logs/`는 새 PC에서 다시 생성한다.
3. Unity Hub에서 `ProjectSettings/ProjectVersion.txt`의 `6000.5.10f1`로 열고 패키지 임포트가 끝나면 `Assets/Scenes/IngameScene.unity`를 연다. Console의 컴파일 오류, 키보드·터치 이동, 자동 공격, 카드 정지·복귀부터 확인한다.
4. 신규 스크립트가 보이는지 확인한다. 이름을 정리한 번개와 무속성 흔적에는 각각 기존 GUID `31aec8b8399aea74ea415566a39ec551`, `573ce27a09a8cdc458db741d7972e143`가 있어야 한다. 컴파일과 기존 전투 재생을 확인한 뒤 M2에서 카드·자동 발동을 연결한다.

- **다음 작업** — M1에서 새 PC 기준으로 씬을 임포트해 기존 전투를 확인한 뒤, M2에서 기존 물·불 동작을 유지하며 번개의 카드 획득·자동 발동·HUD를 연결한다. 보유 상한과 Stage 5 종료 규칙은 사용자 판단을 기다린다.
