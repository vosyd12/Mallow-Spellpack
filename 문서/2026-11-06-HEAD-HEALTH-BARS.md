# 머리 위 공통 HP바 UI

## 작업 범위

- 사용자의 코드 수정 제외 요청에 따라 C# 스크립트를 추가·수정하지 않고 UI 프리팹·캐릭터 배치·도약 추종용 Animation 곡선만 준비했다.
- 공통 원본은 `Assets/Prefab/UI/HealthBar.prefab`이다. 어두운 배경과 빨간 `Fill` Image로 구성하며 World Space Canvas, Sorting Order 100, Raycast Target 꺼짐을 사용한다. 별도 입력 컴포넌트는 없다.
- Fill은 Filled / Horizontal / Left / Fill Amount 1로 설정했다. 실제 HP를 읽는 연결은 없으며 현재는 모든 바가 가득 찬 미리보기 상태다. 체력 수치나 피해·사망 처리는 바꾸지 않았다.

## 위치와 크기

| 대상 | 루트 기준 월드 높이 | 월드 폭 / 높이 |
| --- | --- | --- |
| Player | 0.57 | 0.70 / 0.10 |
| SlimeSmall | 0.32 + 도약 높이 | 0.60 / 0.10 |
| SlimeMedium | 0.40 + 도약 높이 | 0.70 / 0.10 |
| SlimeLarge | 0.50 + 도약 높이 | 0.85 / 0.10 |

- 플레이어는 SampleScene의 Player 자식으로, 슬라임은 각 Prefab의 `HealthBarMotion` 아래에 공통 HP바 인스턴스를 연결했다. 생성되는 슬라임도 같은 UI를 가진다.
- 캐릭터 루트의 비균등 Scale을 UI 인스턴스의 Scale로 보정해 바가 찌그러지지 않게 했다. 표의 크기는 현재 루트 Scale 기준이며 이후 루트 Scale을 바꾸면 보정값도 확인해야 한다.
- 슬라임의 기존 9개 클립에 `HealthBarMotion` 위치 곡선만 추가했다. 기존 `VisualRoot` 위치 곡선과 동일한 높이를 적용하고 Scale 곡선은 추가하지 않아 도약·공격 시 머리를 따라가되 몸체 압축은 받지 않는다. 이후 도약 높이 곡선을 바꿀 때 UI 높이 곡선도 함께 맞춰야 한다.

## 이후 코드 연결 지점

- 각 HP바의 `Fill` Image의 `fillAmount`에 현재 HP / 최대 HP 비율을 전달하면 된다. Inspector에서 Fill Amount 0·0.5·1로 수동 미리보기가 가능하다.
- 현재 UI는 실제 HP가 0인지 판단하거나 HP에 맞춰 숨겨지지 않는다. 최대 HP가 양수인 데이터와 표시용 코드 연결은 사용자가 이어서 구현한다.

## 확인 결과와 남은 확인

- 공통 프리팹·씬·슬라임 3종의 fileID 참조·계층과 Filled 설정을 검사했다. 9개 클립의 런타임·편집용 위치 바인딩, 몸체와 같은 높이 곡선, UI Scale 애니메이션 부재 등 396개 정적 검사를 통과했다.
- 기존 캐릭터와 전투 코드, 체력 설정은 이번 작업에서 수정하지 않았다. MCP는 사용하지 않았다.
- 실제 Unity 화면에서의 위치·가독성·렌더링과 점프 중 추종은 실행 검증하지 않았다. UI 설정 완료와 실제 체력 연동 완료는 구분한다.
