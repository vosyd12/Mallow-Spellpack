# 화염 장판과 공통 스킬 발동 설계 검토

11월 18일에 복구한 워터볼을 기준으로 화염 장판의 다음 작업을 검토했다. 씬의 기준 경로는 `Assets/Scenes/IngameScene.unity`다. 워터볼의 참조 오류, 복구 과정과 실제 재생 결과는 [11월 18일 기록](2026-11-18-WATERBALL-SCENE-REFERENCE.md)에 있다.

## 현재 코드와 씬

| 대상 | 11월 19일 파일에서 확인한 내용 |
| --- | --- |
| 워터볼 | `PlayerSkill.Update()`가 워터볼만 자동으로 검사한다. 씬에서 올바른 `WaterBall` 컴포넌트와 첫 슬롯이 연결돼 있으며 쿨다운 저장값은 3초다. |
| 화염 장판 | `SkillSlotUI`에서 `PlayerSkill.UseFireArea()`를 호출하는 수동 경로가 있다. `FireAreaSkill`은 사거리 안의 현재 타깃 위치에 장판을 생성하고, `FireArea`는 원 안의 적에게 일정 간격으로 피해를 준다. 같은 적의 Collider가 여러 개여도 한 번의 피해 판정에서 한 번만 처리한다. |
| 화염 장판 연결 | `IngameScene`에서 `PlayerSkill._fireAreaSkill`이 비어 있다. 장판 스크립트를 사용하는 Prefab과 씬 슬롯 배정은 저장된 파일에서 확인되지 않았다. 자동 발동, 연출, 실제 게임 재생 검증이 남아 있다. |
| 공통화 초안 | `SkillState.cs`와 `SkillBehaviour.cs`는 빈 Unity 템플릿이다. `SkillData`에는 속성·형태·기본 피해·쿨다운과 현재 레벨이 있고, 스킬 트리와 공통 발동 경로는 아직 구현되지 않았다. |

화염 장판의 **코드 기본값**은 사거리 6, 반지름 1.5, 지속 3초, 피해 간격 0.5초, 1레벨 피해 5, 쿨다운 5초다. 장판은 소유자가 행동할 수 없거나 수명이 끝나면 제거하도록 작성돼 있다. 이 값과 동작은 코드에서 확인한 초안이다.

## 중복의 원인과 설계 제안

현재 `PlayerSkill`에 스킬별 발동 함수와 쿨다운 필드가 있고 `SkillSlotUI`도 스킬별로 분기한다. 이 방식으로 자동 장판을 추가하면 스킬마다 입력·자동 검사·쿨다운·슬롯 표시의 연결을 다시 작성하게 된다. 스킬 트리가 개별 스킬 함수를 직접 호출하면 같은 구분이 해금과 강화에도 반복된다.

1. `SkillData`에 스킬 ID, 속성, 형태, 기본 피해, 기본 쿨다운 같은 공통 설정을 둔다. 현재 레벨·자동/수동 모드·다음 발동 가능 시각은 플레이어가 보유한 스킬마다 관리한다. 이 값들을 `SkillData`와 한 타입으로 둘지 별도 `SkillState`에 둘지는 미정이다. 공통 정의를 여러 곳에서 공유한다면 플레이어의 변경값을 정의와 분리하는 쪽이 적합하다.
2. 기존 워터볼과 화염 장판의 `TryCast` 호출 형태를 맞춘다. `PlayerSkill`은 등록된 자동 스킬을 검사하고 발동 성공 시 그 스킬의 쿨다운을 시작한다. 슬롯은 스킬 ID로 상태를 읽고 수동 입력도 같은 발동 경로에 전달한다. 공통 호출에는 `SkillBehaviour` 기반 클래스와 인터페이스 중 하나면 충분하며, 구체 방식은 미정이다.
3. 물·불 등의 속성과 투사체·장판 등의 형태를 조합한다. 새 속성의 투사체나 장판이 기존과 같은 방식으로 생성되고 피해를 준다면 실행 구현을 공유한다. 형태별 인터페이스만으로는 생성·충돌·피해 코드가 공유되지 않는다. 다음 속성 스킬에서 공통 동작이 확인되면 `ProjectileSkill` 또는 `AreaSkill` 추출을 검토한다.

이 구조에서 기대하는 변화는 스킬 트리가 해금 시 공통 목록에 스킬을 등록하고, 강화 시 현재 레벨을 갱신하는 것이다. 장판의 최종 수치·자동 표적 선택·중첩 규칙, 사망 시 장판 쿨다운 정책은 미정이다. 워터볼의 사망 시 쿨다운 초기화는 [기존 확정 요구사항](2026-11-18-WATERBALL-FOLLOW-UP.md)으로 별도 추적한다.

## 후속 대화에서 검토한 구조

- **검토 중 · 데이터와 상태** — 별도 `SkillState`에 두려던 내용을 `SkillData`로 통합하는 방향을 논의했다. 공통 설정은 `SkillData`에 모으고, 남은 쿨다운처럼 실행 중 달라지는 값은 우선 기존 `PlayerSkill`에서 관리하는 안을 제안했다. 현재 `SkillData`에는 레벨이 있고 `SkillState.cs`는 빈 템플릿이다. 레벨과 모드를 최종적으로 어디에 둘지는 미정이다.
- **검토 중 · 동작 재사용** — 스킬이나 속성을 추가할 때마다 파일이 늘어나는 문제를 줄이고자 한다. 투사체·장판처럼 같은 동작은 재사용하고, 실제로 달라지는 속성 효과만 별도 구현하는 안을 검토했다. 예를 들어 불 장판과 얼음 장판의 동작이 같다면 설정과 Prefab을 바꿔 같은 장판 로직을 사용할 수 있다.
- **검토 중 · 인터페이스** — 인터페이스에는 `TryCast` 같은 공통 호출 규칙을 두는 안이 있다. 공통 피해 계산과 쿨다운 처리 자체는 기존 공통 코드에 둔다. 인터페이스 도입 여부와 함수 형태는 확정하지 않았다.
- **미정 · 불의 고유 효과** — 현재 코드는 적이 있던 위치에 고정된 원형 장판으로, 범위 안의 적에게 반복 피해를 준다. 장판 밖으로 나간 뒤에도 연소를 적용할지는 사용자 판단을 기다린다.

## 다음 작업과 확인 기준

1. 현재 제안은 화염 장판을 먼저 연결해 기준 동작을 확인하고, 같은 형태의 다른 스킬에서 실제로 겹치는 동작을 확인한 뒤 공통화 범위를 정하는 것이다.
2. 장판 Prefab에 `FireArea`와 불꽃 연출을 구성하고 `IngameScene`에서 `FireAreaSkill` 및 사용할 슬롯을 연결한다. 두 스킬의 공통 발동 경로를 적용할 때는 발동 성공 시 각 스킬의 쿨다운이 독립적으로 시작되는지 확인한다. 씬을 저장하고 다시 열어 스크립트와 슬롯 참조를 확인한다.
3. Play Mode에서 워터볼과 기본 공격의 기존 동작, 화염 장판 자동 발동, 범위 피해와 만료, 두 슬롯의 쿨다운 표시를 확인한다. 범위 밖의 적과 재시작 중 발동 차단도 확인한다.
