# 화면 비율 대응 UI 기준 정리

**이 방식은 폐기됨:** 사용자 의도와 다른 고정 폭 HUD 방식이었다. 같은 날 후속 작업에서 전체 화면 Stretch·화면 폭 비례 배율·패널 비율 앵커로 교정했다. 아래 내용과 화면 캡처는 이전 작업 기록이며 [현재 설정과 확인 범위](2026-11-16-FLUID-UI-CORRECTION.md)를 따른다.

작성일: 2026-11-16. 사용자 허가 후 Unity MCP로 SampleScene을 편집·저장했다. C#·카메라·캐릭터/적 스탯·공격·스킬 코드는 수정하지 않았다.

## 문제와 원인

Canvas가 있어도 모든 배치가 같은 비율로 유지되는 것은 아니다. 기존 HUD는 1080×1920, Match 0.5 기준으로 크기를 조절했고 TopHUD가 화면 전체 폭으로 늘어났다. 자식 패널의 폭은 부모 비율, 높이는 고정값이어서 화면이 넓어질 때 패널 모양이 달라졌다. 임시 스킬 자리 두 개는 화면 중앙 기준의 큰 음수 좌표로 배치돼 화면별 위치가 안정적이지 않았다.

## 적용한 기준과 변경

- HUDCanvas와 씬의 ScreenTransition Canvas Scaler를 `Scale With Screen Size`, 기준 `1080×1920`, `Expand`로 통일했다. 가로·세로 배율 중 작은 값을 사용해 기준 UI가 화면 안에 들어오도록 한다.
- TopHUD를 상단 중앙 앵커·상단 중앙 피벗, 위치 `(0,0)`, 기준 크기 `1080×220`으로 고정했다. 패널 내부 폭·높이가 같은 비율로 축소/확대되며 넓은 화면에서는 좌우 여백이 생긴다. 화면 전체를 같은 구도로 고정하거나 레터박스를 만든 구현은 아니다.
- 캐릭터 정보·경험치·Stage/보스 게이지의 기존 이미지·텍스트·버튼 이벤트는 유지했다.
- 요청한 `첫번째 스킬 자리`와 `두번째 스킬 자리` Image 오브젝트를 삭제했다. 스킬 파일과 실제 전투 코드는 삭제하지 않았다.
- ScreenTransition은 기존 전체 화면 앵커와 애니메이션을 유지한다. 이번 Scaler 변경은 씬 인스턴스에 적용했으며 Prefab 원본은 바꾸지 않았다.
- 캐릭터/적 HP바는 World Space Canvas로 유지했다. 화면 HUD의 고정 위치 규칙을 머리 위 HP바에 적용하지 않는다.

## 확인 결과

MCP에서 임시 스킬 자리 삭제 후 HUDCanvas 자식이 TopHUD 하나인지 확인했다. 현재 Game View `690×869`에서 실제 Play를 실행해 상단 HUD 표시와 임시 자리 제거를 확인했고 콘솔 오류 조회는 0개였다. 확인 후 Play를 종료하고 씬을 저장했다. 기존 미저장 씬 편집은 함께 보존했다.

- [실제 Game 화면](검증자료/2026-11-16-화면UI기준/GameView-690x869.png)
- [설정·해상도별 배치 계산](검증자료/2026-11-16-화면UI기준/LayoutChecks.json)

1080×1920, 1080×2340, 1080×2400, 1536×2048, 1920×1080은 저장한 앵커·기준 크기·배율식으로 패널 경계가 화면 안에 있는지 계산했다. 이 다섯 크기를 Unity Game View에서 각각 재생·촬영한 것은 아니다. 계산상 패널 비율 유지와 실제 모든 해상도에서의 가독성 확인은 구분한다. 초기 편집 모드의 카메라 캡처는 Overlay UI를 포함하지 않아 UI 전후 비교 자료로 사용하지 않았다.

## 남은 범위와 코드 경계

이번에 정리한 것은 **화면 고정 UI의 크기·앵커 기준**이다. 기존 Orthographic Camera 크기 7.5와 전투 공간은 유지했다. 화면 비율이 달라지면 카메라의 가로 표시 범위가 달라지는 동작은 그대로이므로 맵·캐릭터까지 항상 같은 구도로 보이도록 완료한 것이 아니다.

월드 구도까지 비율에 따라 맞추려면 카메라 범위/Viewport의 동적 대응을 별도로 설계·구현해야 한다. AGENTS의 사용자 주도 코드 작업 규칙에 따라 이번에는 추가하지 않았다. 카메라 추적과도 별개의 과제로 남겼다.

향후 하단 스킬·우측 메뉴는 각각 화면 하단/우측을 기준으로 앵커와 기준 크기를 정하고, 현재 임시 좌표 배치를 재사용하지 않는다. 메뉴 토글·스킬 버튼 제작·새 화면 전환은 이번 작업에 포함하지 않았다. UI 기본 기준과 추후 개별 배치의 가독성 확인은 계속 구분한다.
