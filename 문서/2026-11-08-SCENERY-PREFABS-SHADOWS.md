# 배경 Prefab·타입별 배치와 공통 그림자

작성일: 2026-11-08. 사용자 승인 시안을 에셋·Prefab으로 적용하고 MCP에서 연결·표시·재배치를 확인했다. 이 배경·그림자 적용 작업에서 변경한 C#은 `StageScenery.cs`다. 다만 AI가 연결 요청을 코드 수정 허가로 확대 해석한 작업이었다. 권한 판단의 문제와 이후 역할 정리는 [구조 검토·협업 기록](2026-11-08-STAGE-SCENERY-DESIGN-REVIEW.md)을 따른다. `Stage.cs`와 전투·이동 C#은 이 배경·그림자 적용 작업 전 상태를 유지했다.

## 요청과 변경 이유

사용자는 4타입 아트 시안을 승인하고, 같은 품질의 Prefab 제작·타입별 3~4개 랜덤 배치·개별 개수 조절·카메라 쪽 광원을 가정한 그림자 통일을 요청했다. 기존 14개 나무는 고정 배치였고, 초기 StageScenery는 나무와 나머지 장식을 두 묶음으로만 관리해 작은 장식의 개수를 따로 조절할 수 없었다.

타입별 설정을 한 배열로 묶고 같은 배치 함수를 재사용했다. 새 장식 타입마다 실행 코드나 Update를 추가하지 않도록 했다. 위치는 지정한 후보 중에서 추첨해 중앙 전투 공간과 나무의 외곽 배치를 유지한다.

## 적용 구성

| 타입 / Inspector 그룹 이름 | Prefab |
| --- | --- |
| 나무 / Tree | MeadowOakRound, MeadowOakTall |
| 풀숲 / GrassClump | MeadowGrassClumpA, MeadowGrassClumpB |
| 꽃이 핀 풀숲 / FlowerBush | MeadowFlowerBushA, MeadowFlowerBushB |
| 작은 꽃 무리 / Flowers | MeadowFlowersA, MeadowFlowersB |

- 이미지: `Assets/Sprites/Environment/Meadow/Props/MeadowPropsAtlas.png`. 내장 imagegen으로 승인 시안을 투명 배경 에셋으로 변환했다. 실제 출력 1774×887을 Sprite 8개로 나누고 기존 시안의 형태·명암·외곽선을 유지했다.
- Prefab: `Assets/Prefab/Environment/`. 각 Prefab은 Visual과 접지·투영 그림자로 구성하며 충돌체가 없다. 기존 나무 2종은 GUID를 유지하며 새 승인 이미지로 변경했다.
- 공통 그림자 기준: `Assets/Prefab/Effects/CameraGroundShadow.prefab`. 기존 `GroundShadowMask`를 재사용하며 색 RGB는 (0.08, 0.14, 0.10), 접지 기본 alpha 0.23, 투영 alpha 0.13이다. 투영 중심은 그림자 너비의 오른쪽 0.20 / 아래 약 0.082로 옮긴다.
- Stage Prefab에 Stage·StageScenery를 연결했다. `Stage.Start → EnterStage → Rebuild`로 최초 배치하고 이후 EnterStage 호출 때 재배치한다. 보스 처치·재도전·실제 다음 스테이지 진입 조건은 이번 구현에 포함하지 않았다. 같은 번호로 EnterStage를 다시 호출해도 재추첨한다.
- `Scenery`는 생성 장식만 담고, `ScenerySpawnPoints` 아래에 타입별 후보 지점을 둔다. 나무 후보 14개, 다른 타입은 각각 12개다. 이전 고정 나무 14개는 제거해 이중 배치를 방지했다.
- 4그룹의 CountRange는 각각 (3, 4)다. 기존의 작은 장식 합계 3~4개 구상에서 현재 요청에 맞춘 **타입별 3~4개, 총 12~16개**로 변경했다.
- 후보는 한 번 뽑으면 해당 추첨에서 제거하며, 생성물 중심의 최소 간격 0.65월드 단위도 확인한다. 작은 위치 변화는 반경 0.14, 나무 배율은 0.65~0.8, 나머지는 0.9~1.1이다. 현재 조절용 설정값이며 최종 밸런스 규칙은 아니다.
- 재배치 때 자신이 생성한 개체를 먼저 비활성화하고 Destroy한다. 매 프레임 배치·물리 탐색·풀링을 추가하지 않았다. 후보 공간이 부족하면 가능한 수만 만들고 경고한다. 최소 간격은 중심 기준이며 그림 전체의 겹침을 완전히 방지하는 판정은 아니다.

## 그림자 정리와 표시 결함 해결

모든 장식과 플레이어, 기본 슬라임 3종·속성 슬라임 18종에 같은 마스크·색 기준과 투영 방향을 적용했다. 실시간 Light2D·ShadowCaster나 정확한 실루엣 투영이 아니라, 카메라 쪽 왼쪽 위 광원을 가정한 저비용 2D 표현이다.

처음 실제 화면에서는 그림자가 너무 얇고 플레이어 그림자가 몸에 묻혔다. 원인은 그림자 Sprite의 정사각형 투명 여백까지 크기로 계산하고, 플레이어 외형 대신 숨겨진 루트 Square Renderer를 기준으로 삼은 것이다. PNG의 실제 불투명 픽셀 영역과 화면에 보이는 Visual Renderer를 읽어 발 위치·너비를 다시 계산했다. 이 픽셀 분석은 Editor 설정 작업에서만 실행했고 게임 실행 중 이미지 읽기 코드를 추가하지 않았다.

이미지 생성물의 행 경계에 있던 다른 Sprite 일부가 꽃풀숲의 빈 영역으로 포함되는 문제도 확인해, Unity에서 Sprite 분리 영역을 보정했다. PNG 픽셀을 별도 편집하지 않았다.

슬라임의 기존 `GroundShadow/ShadowPulse` 경로·컴포넌트는 보존했다. 본체 도약과 분리된 위치를 유지하고 기존 9개 클립의 접지 alpha를 0.10~0.26 범위로 보정했다. 투영 레이어는 기본 alpha를 유지하며 부모의 크기 변화를 따른다. 플레이어는 실제 Visual Sprite의 발밑에 배치했다.

## Prefab 재저장 후 생성 참조 복구

그림자를 추가하며 Unity에서 Variant를 저장한 뒤, 수동으로 구성됐던 Enemy 컴포넌트의 stripped 내부 번호가 갱신됐다. 씬의 EnemySpawner는 예전 번호 `7100000000000000100`을 참조해 18개 슬롯이 모두 null이 되고 적 조합 누락 경고가 발생했다.

이번 작업 전 씬의 Prefab GUID와 순서를 대조하고, 같은 18개 Prefab에서 현재 Enemy 컴포넌트를 다시 얻어 Inspector 참조를 갱신했다. 전투 코드는 변경하지 않았다. 새 로컬 번호는 `6657811535022214718`이며 GUID와 함께 사용된다. 다시 임포트한 뒤에도 18개 조합이 모두 조회되는지 확인했다. 앞으로 Prefab 저장 후에는 Prefab 자체의 임포트와 외부 컴포넌트 참조 유효성을 함께 확인한다.

## 개별 수량·외형 조절

1. `Assets/Prefab/Stage.prefab`을 열고 StageScenery의 Groups를 펼친다.
2. Tree·GrassClump·FlowerBush·Flowers 각각의 CountRange를 변경한다. 예: (3, 4)는 3~4개, (6, 6)은 6개, (0, 0)은 해당 타입을 배치하지 않는다.
3. Prefabs는 외형 후보, SpawnPoints는 배치 후보, ScaleRange는 크기 변화 범위다. 개수를 많이 늘리면 후보 지점도 추가한다.
4. 그림자는 공통 CameraGroundShadow Prefab을 기준으로 조정한다. 장식 인스턴스에는 크기 보정 override가 있고, 슬라임은 Animation 바인딩 보존을 위해 같은 마스크·값을 기존 ShadowPulse에 적용한 구성이다.

## 확인한 결과와 남은 범위

- 두 Stage 파일을 실제 Unity 참조로 컴파일해 오류가 없었다. 단독 컴파일에서는 Inspector 할당 필드의 CS0649 경고가 나며, 실제 씬 연결을 별도로 확인했다.
- MCP에서 최초 배치 3/4/3/3개, EnterStage(2) 후 4/4/4/4개와 서로 다른 위치·외형을 확인했다. 최소 중심 간격은 각각 약 0.93 / 0.65 이상이었다. 실제 값은 검증 JSON에 남겼다.
- Play Mode에서 나무만 1개, 꽃만 6개로 바꾼 뒤 EnterStage(3)를 호출해 개별 변경을 확인했다. 이전 생성물이 쌓이지 않았고, 이 임시 값은 저장하지 않았다. 종료 후 에셋은 모두 (3, 4)다.
- 슬라임 18종을 통제 배치해 착지·도약 포즈를 캡처했다. 모든 그림자는 본체 VisualRoot 밖에 있고, 점프 포즈 변경 시 그림자 중심 이동은 0이었다. 투영 방향은 모두 오른쪽 아래다. 이는 포즈 재현이며 모든 자연 전투 상황의 검증은 아니다.
- 적 생성 참조 복구 후 실제 적 5종 개체가 생성되어 움직이는 화면을 확인했다. 마지막 실행의 오류·경고는 0개였다. 복구 전 경고와 실행 도중 발생한 외부 MCP/Unity AI 플러그인 메시지는 별도 원본 기록에 보관했다.
- 이동 경계·카메라·충돌체는 유지했다. 마지막에 Play·Pause를 끄고 카메라 7.5, 백그라운드 실행 false, 스테이지 번호 1, 씬 수정 표시 없음으로 복원했다.
- 모바일 실기기·장시간 전투·대량 장식의 성능은 측정하지 않았다. CPU/FPS 개선율을 주장하지 않는다. 랜덤 생성의 완전한 재현·저장용 시드는 아직 없고, 최종 밀도·색·그림자 농도는 사용자 피드백으로 조정한다.
