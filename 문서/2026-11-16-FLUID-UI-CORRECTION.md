# 화면 크기에 비례하는 UI 배치로 정정

**후속 상태:** 사용자 확인에서 UI만 커지고 Stage·캐릭터와의 비율이 맞지 않는 문제가 제기됐다. 이후 사용자가 최상위 IngameScene Canvas와 1980×1080 기준을 구성했다. 아래 UI 폭 비례 수정과 계산은 당시 기록이며 현재 구조의 정상 동작을 증명하지 않는다. [현재 Hierarchy·미완료 상태](2026-11-16-HIERARCHY-STATE.md)를 따른다.

작성일: 2026-11-16. 사용자 지시에 따라 MCP를 사용하지 않고 저장된 씬·UI Prefab 설정만 수정했다. 현재 게임 씬은 `Assets/Scenes/SampleScene.unity`다. C#·에셋 GUID·게임 상태/전투 로직은 변경하지 않았다.

## 잘못된 해석과 원인

사용자는 화면이 커지면 UI도 함께 커지고, 작아지면 함께 작아지면서 상대적인 위치가 유지되기를 원했다. AI는 이를 기준 크기의 HUD 묶음을 화면 안에 유지하는 것으로 좁혀 TopHUD를 1080×220으로 고정하고 Expand 배율을 적용했다. 그 결과 넓은 화면에서도 상단의 작은 영역에 묶여 화면 폭을 활용하지 못했다.

이전 작업은 한 해상도에서 표시되는 것만 확인하고 다른 비율의 검증을 계산으로 대신했다. 오류 로그가 없다는 사실도 배치가 적절하다는 근거로 사용하면 안 된다. 해당 고정 폭 방식은 폐기한다. 현재 파일에는 캐릭터 정보 패널의 중앙 앵커·큰 음수 X 좌표도 남아 있어 화면 밖으로 밀릴 수 있었으므로 함께 정리했다.

## 선택한 해결 방법

- TopHUD의 앵커를 화면 전체 Stretch로 바꾸고 Size Delta·위치 오프셋을 0으로 설정했다. 상단 묶음의 고정 폭 1080·고정 높이 220은 제거했다.
- HUD Canvas Scaler를 `Scale With Screen Size`, 제작 기준 `1080×1920`, `Match Width Or Height / Width(0)`로 설정했다. 실제 배율은 **화면 폭 ÷ 1080**이다. 기준값 1080은 제작 좌표이며 화면에 표시할 폭을 제한하는 값이 아니다.
- 캐릭터 정보는 화면 폭의 1.5~24.5%, Stage 정보는 25.5~75.5% 구간을 사용한다. 패널과 내부 글자·아이콘·버튼·여백이 동일한 Canvas 배율로 변한다. 높이를 가로와 독립적으로 늘려 이미지를 찌그러뜨리지 않는다.
- 캐릭터 정보의 중앙 앵커·음수 위치를 좌상단 비율 앵커로 바꿨다. 기존 텍스트·버튼 이벤트·PlayerInfo/StageInfo 참조는 유지했다.
- 암전 Canvas는 Prefab 원본과 씬 Override 모두 같은 Width 기준으로 맞췄다. 전체 화면 Stretch와 Cover/Reveal 애니메이션은 유지한다.
- 이미 삭제한 첫번째·두번째 임시 스킬 자리는 복구하지 않았다. World Space HP바·월드 카메라·캐릭터/적 크기는 이번 UI 배치 수정에서 변경하지 않았다.

## 크기 변화 예시

| 화면 크기 예시 | UI 배율 | 캐릭터 정보 패널 크기(px) |
| --- | --- | --- |
| 360×640 | 0.333 | 82.8×64.7 |
| 1080×1920 | 1.000 | 248.4×194.0 |
| 904×2316 | 0.837 | 207.9×162.4 |
| 1840×2208 | 1.704 | 423.2×330.5 |
| 1800×1800 | 1.667 | 414.0×323.3 |

이 크기들은 배율을 확인하기 위한 예시이며 특정 폴드 모델의 지원 인증 결과가 아니다. 가로 폭이 같고 높이만 늘어난 경우에는 UI 크기를 유지하고 세로 공간을 더 사용한다.

## 확인 결과와 한계

저장된 앵커·피벗·자식 관계로 HUD RectTransform 21개의 경계를 계산했다. 위 예시와 1080×2400·1536×2048·1920×1080을 포함한 8가지 크기에서 화면 안에 있는지, 두 패널의 종횡비가 유지되는지 확인했다. C#·메타·기준 아틀라스 등 보호 대상 310개 파일은 변경하지 않았다. [설정과 계산 결과](검증자료/2026-11-16-UI유동배치수정/LayoutChecks.json)

이번에는 MCP·Unity 실행·새 Game View 캡처·실기기 검증을 하지 않았다. 기존 690×869 캡처는 폐기한 고정 폭 방식의 화면이며 이번 수정 결과로 사용하지 않는다. 실제 폰트 가독성·입력 영역·펼침 중 기기 전환은 사용자 실행 확인이 필요하다. 계산 통과를 실제 화면 검증 완료로 보고하지 않는다.

열려 있는 Unity가 이전 씬 상태를 계속 표시하면 디스크의 SampleScene을 다시 불러온 뒤 확인한다. 미저장 사용자 편집이 있는 경우 그것을 먼저 보존해야 하며, 이전 씬 메모리 상태로 저장해 이번 파일 변경을 덮어쓰지 않도록 구분한다.

## 현재 기준과 후속 범위

현재 기준은 화면 폭에 비례하는 HUD 배율과 화면 기준 상대 배치다. 새 메뉴·스킬 UI도 이 부모 Canvas의 배율과 앵커를 사용한다. 카메라 추적·전투 구도의 동적 대응·HealthBar 디자인 개선은 별도 과제이며 이번 수정으로 완료 처리하지 않는다.
