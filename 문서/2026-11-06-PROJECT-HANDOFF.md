# 프로젝트 공유와 재개 기록

2026-11-06. 현재 프로젝트와 문서를 GitHub `vosyd12/Mallow-Spellpack`에 공유하기 위해 정리했다.

## 공유 상태

저장 파일의 대조 기준은 [현재 코드·설정 지문](2026-11-06-CURRENT-SOURCE.json)이다. 과거 실행/성능 기록의 지문은 해당 기록에 따로 보존한다.

로컬 폴더에 .git이 없어 저장소를 초기화하고 원격 main의 초기 체크인 `e432b0c` 이력을 가져왔다. 현재 Assets·Packages·ProjectSettings·규칙·문서·이미지·계측 자료를 그 후속 커밋으로 올리는 범위다. 사용자 C#을 임의로 고치지 않고 미완료 연결도 문서에 표시했다. 푸시 결과의 커밋은 Git 이력과 작업 종료 보고에서 확인한다.

GAME_DESIGN.md는 사용자가 아직 확정 규칙이 없다고 명시했으므로 작성 기준을 유지했다. 현재 구현값을 확정 기획으로 승격하지 않았다. 마일스톤에는 생성·이동·탄환·풀링과 남은 타깃 연결을 코드 기준으로 표시했다. AGENTS에는 합의한 문제 해결 기록 항목을 보완했다.

## 다른 환경에서 시작

1. [루트 README](../README.md)와 [AGENTS](../AGENTS.md)를 읽는다. 코드 작성은 사용자 주도, AI는 보조라는 전제를 유지한다.
2. Unity 6000.5.10f1, Packages와 lock 파일, 모든 에셋/.meta를 함께 복원한다. 이미지가 LFS 포인터로 남으면 Git LFS로 실제 파일을 가져온다.
3. [현황 문서](README.md)에서 남은 문제와 관련 코드를 확인한다. 미확정 기획이나 과거 제안값으로 현재 파일을 덮어쓰지 않는다.
4. SampleScene을 연 뒤 Console·Inspector를 확인한다. 문서의 과거 실행 결과를 새 환경의 실행 성공으로 간주하지 않는다.

MCP 패키지 의존성은 있지만 서버 연결·로컬 주소·AI 서비스 로그인은 환경마다 다르다. 일반 문서화나 Git 공유를 이유로 MCP·Notion을 자동 연결하지 않는다. 이번 문서 정리·업로드에서는 둘 다 사용하지 않았다.

## 보존한 것과 제외한 것

새 스프라이트 원본은 프로젝트 안에 있고 Prefab·재질·텍스처의 .meta를 포함한다. 성능 비교 그래프·회차 CSV·원본 측정·코드 지문·측정 코드를 문서 폴더에 보존했다. Library의 임시 실행 코드나 채팅에만 핵심 근거를 두지 않았다.

Library·Logs·UserSettings·obj·IDE 캐시·생성 프로젝트 파일은 업로드에서 제외한다. 비밀정보·개인 저장 자료가 포함되지 않는지 대상 파일을 확인한다. GitHub 커밋은 디스크에 저장된 상태를 공유하며 Unity의 저장하지 않은 편집기 변경까지 자동 포함하지 않는다.

## 종료 시 확인 범위

코드·Prefab/씬 연결·마일스톤 일치와 새 문서 링크를 정적으로 확인한다. 기존 검증과 이번 점검을 구분하며 새 Play·컴파일·성능 검사는 수행하지 않는다. 알려진 타깃 검색 오타·Spawner 참조 누락·공격 대상 연결은 해결한 것으로 기록하지 않는다.
