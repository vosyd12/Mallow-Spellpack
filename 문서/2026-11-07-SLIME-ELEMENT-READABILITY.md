# 이동 중 슬라임 속성 식별 문제 관찰

2026-11-07. 사용자는 맵 전체가 보이는 화면에서 보잉 모션 때문에 슬라임의 속성을 알아보기 어려운지 직접 확인하고, 의심되는 순간을 캡처하도록 요청했다. 이번 범위는 문제 인식이며 개선은 적용하지 않았다.

## 확인 환경

`http://127.0.0.1:8099/mcp`로 실제 `Mallow Spellpack` 에디터에 연결했다. SampleScene의 Spawner가 18종 Prefab을 참조하는 것을 확인하고 Play Mode로 관찰했다. 기존 Main Camera는 위치 `(0, 0, -10)`, 회전 0, Orthographic Size 7.5로 이미 맵 전체가 보이는 상태여서 수정하지 않았다. 캡처는 648×869이며, 비교에 사용한 프레임은 일시정지 후 같은 Main Camera에서 렌더했다.

## 관찰한 문제와 근거

1. **몸과 함께 속성 장식도 크게 변형된다.** 불 Large의 VisualRoot는 눌린 순간 X 1.493 / Y 0.574, 늘어난 표본에서는 X 약 0.732 / Y 약 1.406이었다. 불꽃이 넓고 짧아졌다가 좁고 길어져 일정한 표식으로 읽히지 않는다. 바람 Large도 납작한 자세에서는 소용돌이보다 얼굴·콧수염과 외곽선이 먼저 보였다.
2. **Small의 장식을 읽을 화면 픽셀이 부족하다.** 카메라와 현재 Prefab의 기본 가로폭을 환산하면 Small 몸 전체 폭은 약 17픽셀이다. 도약 중 좁아지면 더 작아지고, 머리 장식은 몇 픽셀 수준으로 줄어든다. 관찰한 땅 Small과 번개 Small에서 색 계열은 보였지만 돌·번개 모양을 즉시 읽기 어려웠다. 이 값은 기본 자세 환산이며 모든 프레임의 실측 폭을 뜻하지 않는다.
3. **개체와 HP바 겹침이 식별을 더 방해한다.** 플레이어 주변에 모인 슬라임들의 장식 근처로 다른 개체와 HP바가 겹쳤다. 넓게 퍼지는 자세에서 구분이 더 어려웠다.

불은 주황색으로 계열을 추정할 수 있었지만, 표식의 형태를 안정적으로 읽는 것과는 차이가 있었다. 바람은 옅은 몸 색과 배경의 대비도 약했다. 색상 데이터가 잘못 바뀌거나 렌더러가 서로 섞인 오류를 확인한 것은 아니다.

## 원인 해석과 개선 후보

현재 몸과 속성 장식은 하나의 Body Sprite이고, 함께 VisualRoot의 스케일 변형을 받는다. 큰 이미지에서 보이는 세부 장식도 전체 맵 크기로 줄이고 강하게 변형하면 식별 단서가 약해진다. 따라서 사용자 피드백은 단순한 취향 차이가 아니라 화면 크기·변형·겹침이 함께 만든 가독성 문제로 판단했다.

개선 후보는 몸의 보잉을 유지하면서 속성 표식의 변형을 줄이는 구조, Small 장식의 최소 표시 크기 확보, HP바와 머리 장식의 간격 조정이다. 아직 선택하거나 구현한 규칙은 아니다. 18종 전체를 다시 그리거나 모션을 줄이는 작업도 하지 않았다.

## 확인 범위와 종료 상태

선택한 실제 캡처의 표본은 불·바람·땅·번개다. 물·무속성, 18종 전부의 크기별 식별성까지 검증한 결과는 아니다. 초반 화면 캡처와 일시정지 비교 캡처를 보존했으며, 이후의 짧은 재개 표본 중에는 백그라운드 실행 때문에 같은 자세가 반복된 것도 있어 주요 근거로 사용하지 않았다. 추가 Play 전환 표본은 전환 대기 상태여서 비교에 포함하지 않았다.

이미지·Prefab·C#·Animation·카메라의 저장 설정을 수정하지 않았다. 관찰 후 Play Mode를 종료하고 편집 모드·카메라 Size 7.5를 확인했다. 마일스톤 구현 체크나 게임 규칙은 변경하지 않았다.
