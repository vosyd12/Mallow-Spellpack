# 수동 조작 적용과 던전 검토 인수인계

현재 작업 씬은 `Assets/Scenes/IngameScene.unity`다. 이동 입력과 모바일 조이스틱을 연결했다. 짧은 1인 던전, 전투력 표시, 던전 안팎 성장 규칙은 검토 중이다.

## 적용한 작업

| 기능 | 현재 동작과 확인 범위 |
| --- | --- |
| 수동 이동 | `Player.cs`가 `Assets/Settings/InputSystem_Actions.inputactions`의 `Player/Move`를 읽고 `Rigidbody2D.MovePosition`으로 이동한다. 키보드 WASD·방향키와 게임패드 왼쪽 스틱이 같은 액션을 사용한다. 기존 자동 회피를 정리했고, 이동 속도는 현재 `_moveSpeed + DEX`를 사용한다. `_moveVelocity`로 걷기를 판정하며 사망·부활 때 값을 비운다. `CanAct`로 보스 등장·사망·재시작 중 이동을 막고, 자동 공격 대상 탐색은 `UpdateTarget()`으로 이어진다. |
| 모바일 조이스틱 | `HUDCanvas/MovementJoystick/Handle`의 `OnScreenStick`을 `<Gamepad>/leftStick`에 연결했다. 하단 왼쪽 고정형이며 Canvas 기준 이동 범위는 47이다. [씬 연결 상세](2026-11-24-TOUCH-MOVEMENT.md) |
| 골드 HUD | 스테이지 패널 아래에 보유 골드를 임시 배치했다. 일반 적은 10골드, 왕관 보스는 100골드를 지급한다. 스탯창을 닫아도 골드가 표시되며 검증용 강화 수치에서 차감도 확인했다. 현재 씬에 저장된 강화 비용·상승량은 각각 0이라 구매 버튼은 잠겨 있다. [골드 HUD와 강화 확인](2026-11-24-PLAYER-STATS-WINDOW.md#골드-hud-임시-배치) |
| 기존 전투·카드 | 워터볼과 화염 장판이 자동 발동한다. 두 스킬의 레벨업 카드가 연결돼 있고 번개 카드는 비활성이다. 현재 스테이지는 처치 목표를 채우면 왕관 슬라임을 생성하고, 보스 처치 후 다음 스테이지로 넘어간다. 15초 타이머는 표시되며 0초 도달 시의 전투 결과는 미구현이다. [기존 전투·성장 검증](2026-11-24-COMBAT-AND-PROGRESSION-HANDOFF.md) |

## 검증 결과

- C# 컴파일과 씬의 입력 경로를 확인했다. Unity 6000.5.10f1 격리 사본에서 동일한 `Player.cs`와 씬을 열고, 가상 터치 드래그, 입력 해제 후 정지, 걷기·대기 전환, W+D 대각선 이동과 자동 기본 공격 시작을 확인했다. 375×808과 450×970에서 조이스틱과 스킬 슬롯이 겹치지 않았다.
- 모바일 실기기 입력 감도와 화면 가장자리에서의 캐릭터 가시성은 추가 확인이 필요하다. 일반 전투 카메라는 고정이다. 보스 등장·사망·재시작 중 입력 차단은 코드로 확인했다.

## 기획과 우선순위

- **확정** — 첫 작업 범위로 캐릭터 수동 이동을 적용하고 기존 자동 공격과 조합한다. 자동 전투의 반복에서 직접 개입할 이유가 약하다는 문제를 먼저 살피기 위해, 스킬 트리보다 수동 전투 확인을 앞당겼다. 최종 장르와 성장 방식은 검토 중이다.
- **검토 중** — 초기 방향인 방치형 성장과 뱀서류 전투를 살려, 직접 이동으로 적 무리의 압박을 피하고 짧은 판 안에서 성장 선택을 체감하는 1인 던전을 검토한다. 첫 실험 후보는 기존 초원 맵, 슬라임 웨이브 2회, 카드 선택 1회, 왕관 슬라임 보스 1마리다. 같은 캐릭터 능력치에서 이동과 카드 선택을 바꿨을 때 전투 결과가 달라지고 다시 도전할 이유가 생기는지를 본다. 판 길이, 승패 조건, 타임아웃 결과, 보상과 재도전 방식은 미정이다.
- **검토 중** — 골드와 영구 강화는 다음 도전에 이어지고, 던전 안에서 고른 카드는 해당 판에서만 적용하는 안을 논의했다. 현재 구현된 레벨업 카드와 스테이지 진행은 기존 규칙을 사용한다. 판 종료 시 카드 효과 초기화와 영구 저장은 미구현이다.
- **검토 중** — 던전 준비도는 보스 상대 예상 초당 피해와 최대 HP를 따로 표시하는 안이 있다. 현재 보스 HP 500을 15초에 깎는다는 가정에서 필요한 평균 피해는 약 33.3/초다. 15초 승패 규칙, 예상 피해 산식, 최종 전투력 표시 형식은 미정이며, 입장은 자유롭게 두는 안을 논의했다.
- **보류** — 스킬 트리 구현 순서는 수동 전투를 확인한 뒤 다시 정한다. 창 시안은 모바일 세로 화면에서 물·불 속성을 탭으로 고르고, 선택한 속성의 특성을 한 열로 보는 방향으로 좁혔다. 보스 보상 포인트, 선행 조건, 해금 효과, 선택 제한과 보존은 검토 중이다. 현재 씬에는 비활성 메뉴 버튼이 있다.

## 초기 기획과 현재 저장소의 차이

초기 기획의 개발 기록에는 기본 스킬 5종·합체 2종과 배낭 프로토타입이 기록돼 있다. 현재 `main` 작업 폴더의 코드와 씬에서는 다음 실행 경로가 확인되지 않았다.

- 플레이어 번개·땅·바람 스킬의 발동과 카드 획득, 동적 슬롯 등록, 스킬별 자동·수동 전환 UI, 패시브와 합체 시 원본 슬롯 교체
- 골드 장비 뽑기, 인벤토리 판매, 배낭·속성석 배치와 전투 효과
- 앱 재실행 시 성장 복원, 오프라인 경험치·골드 정산, 초기 목표였던 고유 스테이지와 보스 구성, 모바일 세로 방향 고정

## 다음 작업 인수인계

- **적용** — `Player.cs`, `Player/Move`, `IngameScene`의 조이스틱이 연결돼 있다. 현재 스테이지와 보스·카드·골드 동작을 시험 기반으로 쓴다.
- **검증** — 파일 대조와 기존 격리 Play Mode 가상 입력 결과를 확인했다. 실기기 확인은 남아 있다.
- **다음 작업** — 이동 감도와 카메라 가시성을 먼저 확인한다. 이후 첫 던전의 웨이브·승패·보상 규칙, 전투력 표시 방식은 사용자 결정을 기다린다.
- **공유 기준** — GitHub `main`의 기준 커밋은 보스전·스탯 성장을 반영한 `fec600b`다. 이 문서를 포함하는 커밋에서 수동 이동 C#·조이스틱·골드 HUD와 최신 기획을 공유한다. 다른 환경에서는 해당 커밋과 현재 씬 상태를 대조한다.
