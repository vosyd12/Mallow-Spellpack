# 슬라임 도약과 몸 변형 과장

이 문서는 첫 조정 기록이다. 이후 더 강한 도약·먼지와 HP바 수정의 최신 수치는 [두 번째 조정](2026-11-07-SLIME-BOUNCE-DUST-HPBAR.md)을 따른다.

작업일: 2026-11-07. 사용자 요청에 따라 외형 Animation 8개를 조정했다. 이동 수치는 사용자가 조정 중이므로 그대로 두었다.

## 문제와 선택 이유

사용자는 슬라임이 더 탄력 있게 눌리고 늘어나는 모습을 원했으나 조절할 수치의 위치를 찾기 어려웠다. SlimeMotion의 `_hopHeight`, `_attackHopHeight`는 현재 먼지 강도 계산용이며 실제 외형 높이는 Animation 클립에 저장된다. 따라서 C#을 추가하거나 이동속도를 바꾸지 않고, 기존 클립의 VisualRoot 위치·크기 곡선을 수정했다.

## 변경 수치

아래 높이는 클립의 로컬 Position Y 최고점이다. 월드 높이는 부모 Scale에도 영향을 받는다.

| 크기 | 일반 도약 전 → 후 | 공격 도약 전 → 후 |
| --- | --- | --- |
| Small | 1 → 1.4 | 2 → 2.4 |
| Medium | 0.75 → 1 | 1.5 → 1.8 |
| Large | 0.5 → 0.65 | 1 → 1.2 |

- 준비 끝 Scale X/Y: 1.12/0.88 → 1.30/0.70.
- 일반 도약의 이륙 직후: 0.91/1.09 → 0.80/1.25.
- 일반 착지 첫 자세: 1.18/0.82 → 1.35/0.70. 이어서 0.86/1.16 → 1.10/0.90 → 0.97/1.03 → 1/1로 반동을 줄인다.
- 공격 첫 착지: 1.35/0.65 → 1.45/0.62. 공중 늘어남과 착지 뒤 반동도 함께 강화했다.
- 준비 마지막과 일반/공격 도약 첫 자세, 일반 도약 마지막과 착지 첫 자세를 맞췄다. 중간 기울기는 각 구간의 증가·감소 방향에 맞게 다시 계산했다.
- HealthBarMotion의 Position 곡선은 VisualRoot와 같은 높이를 따른다. HP바에 몸 크기 변형은 적용하지 않는다.

## 다음에 조절할 위치

`Assets/Animations/Slime/`에서 Animation 창으로 편집한다.

- `SlimePrepare.anim`: 도약 전 몸 압축.
- `SlimeJumpSmall/Medium/Large.anim`: 일반 도약 높이·공중 늘어남.
- `SlimeLand.anim`: 착지 압축·감쇠 반동. 세 크기가 공유한다.
- `SlimeAttackSmall/Medium/Large.anim`: 공격 도약 높이·착지 반동.

높이를 다시 바꾸면 VisualRoot와 HealthBarMotion의 Position Y를 함께 바꾼다. 클립 길이는 1초, 공격 이륙·첫 착지 키는 0.18·0.68로 유지했다. 실제 재생 시간은 각 프리팹의 SlimeMotion Duration 설정으로 결정된다. 먼지 강도 기준값은 이번에 변경하지 않았다.

## 확인 결과와 남은 확인

파일 기준으로 실행용 곡선과 Animation 편집용 곡선의 값·기울기 일치, 기존 키 시각·경로·클립 길이 유지, 상태 경계의 자세 연결을 확인했다. 프리팹·Controller·C#·씬은 이번 작업에서 수정하지 않았다.

예상 효과는 준비 압축과 착지 반동이 더 뚜렷해지고 작은 슬라임이 상대적으로 높이 뛰는 모습이다. Unity 재생·MCP·화면 캡처·성능 측정은 하지 않았다. 사용자는 Play에서 탄력 표현의 과장 정도, HP바 간격과 도약 추종을 확인해야 한다. 이 기록은 HP바 오류나 공격 피해 연결까지 해결·검증했다는 뜻이 아니다.
