# 속성 Dust 표시 수정과 반짝임·번개 바닥 연출

작성일: 2026-11-07. 상태: 에셋 수정·연결 완료, MCP 재생 확인. 기존 C#은 수정하지 않았다.

## 문제와 원인

사용자는 속성별 Dust가 적용되지 않는다고 보고했고, 번개는 바닥 문양을 빛이 훑는 연출로 변경하도록 요청했다. [이전 진단](2026-11-07-ELEMENT-LANDING-SHADER-CHECK.md)에서 입자가 생성되지만 원하는 형태로 표시되지 않는 것을 MCP로 재현했다.

기존 구성은 아틀라스 전체를 재질에 연결하고 Tiling·Offset으로 입자 부분을 선택했다. 프로젝트에 설치된 URP Particles/Unlit의 해당 경로는 이 변환을 UV에 적용하지 않았다. 바람은 Orbital Velocity의 X·Y가 Constant, Z만 TwoConstants여서 경고도 발생했다. 최초 확인을 정상 임포트에서 끝내 실제 렌더링 결함을 놓친 것이 작업상의 원인이었다.

## 해결 방법과 이유

- 5속성 아틀라스에서 착지 입자 Sprite의 rect만 실제 입자 영역과 2픽셀 여백으로 줄였다. PNG 픽셀·몸·장식 rect·GUID·Sprite 내부 ID는 유지했다. 숨김 `.meta`는 기존 파일을 갱신하는 방식으로 기록해 Windows의 쓰기 모드 문제를 피했다.
- Particle System의 Texture Sheet Animation을 **Sprites** 모드로 바꾸고 입자 Sprite 하나를 직접 연결했다. 재질 Tiling·Offset 대신 입자 시스템이 정확한 UV를 제공한다. 무속성은 독립된 기본 먼지 텍스처를 그대로 사용한다.
- `Assets/Shaders/Effects/ElementLanding.shader`를 5속성 재질에 연결했다. 불·물·땅·바람은 입자 표면에 밝은 띠가 지나가며, 번개는 분기된 바닥 문양을 그리는 별도 셰이더 변형을 사용한다.
- Renderer의 스트림을 Position·Color·UV·AgePercent로 설정했다. 수명 비율은 UV 뒤의 `TEXCOORD0.z`로 전달한다. 전역 시간 대신 입자 수명을 사용하므로 풀에서 꺼낼 때마다 처음부터 재생된다. 새 Update·코루틴·재질 인스턴스 생성 코드는 추가하지 않았다.
- 바람의 Orbital X·Y·Z를 모두 Constant로 통일하고 Z 회전값 2.5를 유지했다. 선형 Z 속도는 기존 C#이 설정하는 X·Y와 같은 TwoConstants로 맞췄다.

새 셰이더 초안의 HLSL 예약어 `point` 사용 오류도 이전 단계에서 수정했다. 정상 임포트와 셰이더 메시지 확인만으로 끝내지 않고, 이번에는 실제 렌더링까지 확인했다.

## 번개 바닥 문양

`LandingDustLightning.prefab`은 최대 입자 1개, 수명 0.45초, 가로 1.35·세로 0.75의 고정 문양으로 구성했다. Shape·중력·초기 속도·가로/세로 이동·회전·크기 변화는 끄거나 0으로 맞췄다. 기존 중립 파동 자식도 제거했다. 일반·공격 착지 모두 한 번에 문양 하나를 사용한다.

셰이더는 착지 중심에서 네 방향으로 뻗는 지그재그 선분을 계산한다. 가까운 선분의 진행도를 이용해 밝은 띠가 중심에서 바깥으로 이동하고, 수명 후반에는 문양 전체가 사라진다. 단순히 입자 전체를 깜빡이는 방식과 달리 선을 따라 빛이 진행한다. 2D Stage와 같은 XY 평면에서 캐릭터 뒤·바닥 앞에 그리며 3D Decal이나 새 피해 판정은 추가하지 않았다.

## 조절 위치

| 대상 | 위치·설정 |
| --- | --- |
| 입자 선택 | `LandingDust{속성}.prefab` → Texture Sheet Animation → Sprites |
| 반짝임 색·강도·폭 | `LandingDust{속성}.mat` → Sweep Color / Strength / Width |
| 번개 선 굵기 | 번개 재질 → Ground Line Width |
| 번개 문양 크기·잔류 시간 | 번개 Prefab → Start Size X/Y · Start Lifetime |
| 번개 가지 모양 | 공용 셰이더의 `DrawGroundLightning()` 선분 좌표 |
| 바람 회전 | 바람 Prefab → Velocity over Lifetime → Orbital Z |

## MCP 확인 결과

- 수정 전후 동일한 효과 배치·강도·카메라 크기 4에서 비교했다. 입자 난수와 배경의 자연 생성 효과는 완전히 동일하지 않으므로 픽셀 단위 비교나 성능 비교가 아니다.
- 5속성의 실제 Sprite 선택·공용 셰이더·수명 스트림 연결을 조회했다. 0.05·0.20·0.32초 캡처에서 번개 문양은 같은 바닥 위치에 남고 밝은 띠의 위치는 변했다. 0.20초에 입자 위치 `(0, -1.5, 0)`, 시작 수명 0.45초·남은 수명 약 0.25초를 확인했다.
- 6종 Small Prefab을 Play Mode에서 배치하고 물리 위치를 동기화한 뒤 기존 `SlimeMotion.SpawnLandingDust(false/true)`를 호출했다. 일반 호출에서는 속성에 맞는 효과가, 공격 호출에서는 번개 외 36개·번개 1개 입자가 생성됐다. 이는 착지 함수 경로의 통제된 재현이며 AI가 이동·공격하다 자연 착지하는 모든 상황을 검증한 것은 아니다.
- 일반 재생 후 속성별 풀의 Active 0 / Inactive 6 / All 6을 확인했다. 두 차례 재호출에서도 동일한 개체 ID와 시작 시간 0을 확인했고 각각 다시 전부 반환됐다. 생성 오브젝트 총수는 36개로 유지됐다.
- 최종 콘솔의 오류·경고는 0개였고, 렌더링한 재질의 ShaderUtil 오류도 없었다. C# 해시가 그대로이며 기존 씬 파일도 변경하지 않았다.
- 검증 중 백그라운드 실행을 일시 허용했고 종료 전 false로 복원했다. Play Mode 종료, 씬 수정 표시 없음, 원래 카메라 크기 7.5를 확인했다. 테스트용 개체·전투 비활성화·확대 카메라는 저장하지 않았다.

모바일 빌드·실기기·대규모 동시 재생의 성능은 측정하지 않았다. Bloom은 추가하지 않았으며 현재 반짝임은 재질 자체의 밝기 변화다. 번개 외형의 최종 크기·밝기·밀도는 사용자 피드백으로 조정할 수 있다.
