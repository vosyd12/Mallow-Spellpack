# 플레이어 Walk 클립 단독 제작
작성일: 2026-11-10

## 요청과 적용 범위
기존 v3 파츠로 Walk 애니메이션만 제작했다. C#·씬·프리팹·Idle 클립·Animator Controller는 변경하지 않았으며 자동 전환도 추가하지 않았다. 현재 게임은 기존 Idle을 계속 사용한다.

- [Walk 클립](../Assets/Animations/Player/PlayerMageV3Walk.anim): 0.98초 반복, 60fps 설정, Transform 곡선 20개. 곡선당 33개 키와 연속 접선을 사용한다.
- [실제 Unity 클립 미리보기 GIF](플레이어WalkV3/PlayerMageV3_Walk_Unity.gif): 384×512, 49프레임, 프레임당 0.02초.
- [검증 수치](플레이어WalkV3/Verification.json), [접지 자세](플레이어WalkV3/Walk_Contact.png), [오른발 들기](플레이어WalkV3/Walk_RightStep.png), [왼발 들기](플레이어WalkV3/Walk_LeftStep.png).

## 문제·원인·선택한 방법
기존 GIF는 새로 생성한 이미지 시안이어서 실제 파츠의 움직임과 같지 않았다. 이번에는 현재 프리팹의 Transform을 직접 애니메이션했다. 분리된 연결부가 크게 벌어지지 않도록 작은 보폭을 사용한다.

몸은 주기당 두 번 최대 0.015 로컬 단위 내려갔다 복원되고 좌우로 ±0.004 이동한다. 발은 반 주기씩 교대로 최대 0.035 들어 올린다. 지지하는 발에는 몸의 이동을 반대로 보정해 제자리 미리보기에서 바닥 기준점이 움직이지 않게 했다. 발 회전은 들린 구간에서만 최대 ±2.5도다.

모자와 양갈래는 각각 약 0.06초·0.08초 늦게 반응한다. 로브·팔은 작게 흔들고, 지팡이의 위치·회전을 팔의 회전 중심에 맞춰 함께 계산했다. 손과 지팡이가 각자의 중심에서 회전해 잡은 위치가 벌어지는 문제를 피한다. 기존 Idle의 축소·눈 감김 값이 미리보기에 남지 않도록 Walk에서 관련 크기를 기본값으로 기록한다.

## 실제 확인
MCP의 임시 PreviewRenderUtility에서 기존 프리팹을 복제해 49개 시점을 샘플링했다. 원래 씬의 캐릭터는 조작하지 않았고 임시 오브젝트와 렌더 리소스를 정리했다.
- 지지 구간의 발끝 기준점 오차: 왼쪽 약 0.0000011, 오른쪽 약 0.0000008 월드 단위.
- 손·지팡이 잡는 위치의 최대 오차: 약 0.0000005 월드 단위.
- 시작과 0.98초 끝의 위치·회전·크기 오차: 0. Root Curve 없음, Loop 활성.
- 확대 자세에서 발 교대와 연결부를 확인했다. GIF를 다시 디코딩해 49개 프레임·각 2/100초 지연을 확인했다.
- 현재 Controller는 Idle 한 클립만 참조하며 FirePos는 Staff 자식으로 연결되어 있었다. 씬 dirty=false, 시간·Play 모드 유지, Console 오류·경고 0건을 확인했다.
- C#·프리팹·Idle 클립·Controller는 작업 전후 파일 해시가 모두 일치했다. 씬은 작업 시작 후 Walk 생성 전에 별도로 저장되어 최초 해시와 달랐으며, 이번 작업에서 씬을 저장하거나 되돌리지 않았다. 해당 저장본을 보존했고 검증 전후 dirty=false였다.

## 남은 작업
이 클립은 제자리 Walk이며 게임 이동이나 자동 상태 전환에 연결하지 않았다. 실제 이동 중의 발 미끄러짐·재생 속도 일치는 연동 단계에서 확인해야 한다. 큰 보폭·큰 방향 전환에는 연결부 보완이 여전히 필요하다. GIF는 실제 Unity 프리뷰의 샘플링 결과이며 게임 플레이 녹화가 아니다. 이전 생성 이미지 GIF는 동작 제안 기록으로 보존한다.
