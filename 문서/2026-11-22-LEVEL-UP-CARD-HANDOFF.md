# 레벨업 버튼과 카드 선택 인수인계

레벨업 버튼이 기존 방식으로 레벨을 올리고 HUD를 갱신한다. 다음 작업은 성공 직후 카드를 열고, 카드 입력과 선택 확정을 화면에 보여주는 것이다.

## 확정한 흐름

- **확정** — 버튼이 활성화되면 클릭 한 번에 한 단계 오른다. 카드 패널은 레벨업 성공 직후에 열리도록 한다. 사용자 입력에서 카드가 열리기까지 대기 단계가 생기던 캐릭터의 발밑 빛과 머리 위 `LevelUP` 문구는 롤백했다. [롤백 이력](2026-11-22-LEVEL-UP-EFFECT-ROLLBACK.md)
- **확정** — 카드 연출은 등장, 선택 입력에 대한 반응, 선택된 카드의 확정 표시까지 이어서 작업한다.
- **검토 중** — 카드 장수와 후보 제시 방식, 한 번의 입력으로 확정할지 확인 단계를 둘지, 선택 중 전투 진행, 강화 규칙과 최대 레벨 도달 시 처리. 워터볼과 화염 장판 강화 카드 중 한 장을 고르는 구성은 첫 버전 후보로 검토했다.
- **보류** — 레벨업 버튼이 활성화되는 순간의 알림. 스킬 제작 자동화와 스킬 트리의 우선순위는 기존 결정을 따른다. [기존 우선순위](2026-11-20-FIRE-AREA-SCOPE.md)

## 현재 구현과 검증

| 항목 | 현재 상태 |
| --- | --- |
| 경험치와 레벨 | `Player.TryLevelUp()`은 첫 기준 경험치 100을 시작으로 필요 경험치를 차감하고 레벨을 1 올린다. 다음 기준은 1.1배로 높여 정수로 저장한다. HUD를 갱신한 뒤 `LeveledUp`을 호출한다. [Player.cs](../Assets/Scripts/Player/Player.cs) |
| 레벨업 버튼 | `IngameScene`의 기존 버튼은 `TryLevelUp()`과 Animator의 `Press`를 호출한다. 배경과 글자는 94%로 작아졌다가 0.15초 안에 복원되고, 입력 영역은 원래 버튼 크기를 사용한다. [버튼 설정과 검증](2026-11-22-LEVEL-UP-BUTTON.md) |
| 캐릭터 연출 | 발밑 빛과 머리 위 문구의 씬 참조를 제거했다. 전용 에셋과 메타는 로컬의 `Temp/LevelUpEffectRollback-20261122`에 보관했다. [롤백 범위](2026-11-22-LEVEL-UP-EFFECT-ROLLBACK.md) |
| 카드 스크립트 | 현재 `Assets/Scripts/Effects/LevelUpCardPanel.cs`의 클래스와 동작은 기존 `PlayerLevelUpEffect`와 같다. 같은 메타 GUID를 사용하며, `IngameScene`에 이를 참조하는 컴포넌트와 카드 패널은 아직 없다. [현재 파일](../Assets/Scripts/Effects/LevelUpCardPanel.cs) |
| 스킬 강화 | 워터볼과 화염 장판은 각자의 `SkillData`로 피해량을 계산하며 현재 씬에서 스킬 최대 레벨은 각각 5다. 카드 선택으로 스킬 레벨을 올리는 호출 경로는 작업 대상이다. [공통 피해 계산](../Assets/Scripts/DTO/SkillData.cs) |

롤백 직후 Unity 6000.5.10f1 복제 씬의 Play Mode에서 레벨 1→2→3, 경험치 210→110→0, 성공 이벤트 2회, 버튼 복원과 입력 영역을 확인했다. 이번에 확인한 씬 파일은 캐릭터 연출 적용 직전 파일과 일치한다. 카드 동작과 HUD의 다음 필요 경험치 문구는 이후 실행에서 확인할 항목이다. [롤백 후 재생 결과](2026-11-22-LEVEL-UP-EFFECT-ROLLBACK.md)

## 카드 연출과 강화 연결

먼저 이름이 바뀐 기존 파일을 카드 패널 컴포넌트로 활용할지 정한다. 앞서 제안한 `Assets/Scripts/UI/LevelUpCardPanel.cs`는 카드 UI를 두는 위치의 후보였다. 카드용 클래스 이름과 파일 이름을 맞춘 뒤, 기존 `Player.LeveledUp`을 구독하는 패널 하나로 등장·선택·확정 애니메이션을 연결하는 구성을 검토했다.

첫 선택이 확정된 뒤에는 같은 패널에서 추가 선택을 처리하지 않도록 한다. 선택된 카드의 애니메이션이 끝나면 패널을 닫는 방안과, 실제 강화가 반영된 스킬 슬롯이 짧게 반응하는 방안을 검토했다.

실제 강화를 연결할 때는 `SkillData`에 최대 레벨을 확인하는 공통 메서드를 두고, `WaterBall`과 `FireAreaSkill`이 각자의 데이터에 적용하는 방향이다. 씬에 두 스킬의 데이터가 이미 연결돼 있으므로 카드 선택 뒤 다음 시전의 피해량으로 결과를 확인할 수 있다. [워터볼](../Assets/Scripts/Skill/WaterBall.cs) · [화염 장판](../Assets/Scripts/Skill/FireAreaSkill.cs)

## 다음 작업 인수인계

- **적용** — 레벨업 버튼 반응과 성공 이벤트를 연결했다. 캐릭터의 빛과 문구는 롤백 상태다.
- **검증** — 현재 씬 참조, 카드 파일과 클래스 이름, 두 스킬의 데이터와 최대 레벨을 대조했다. 기존 Play Mode 기록으로 버튼과 레벨업 경로를 확인할 수 있다.
- **다음 작업** — 기존 카드 파일을 사용할지 먼저 정한 뒤, 카드 패널을 만들고 `LeveledUp`에 연결한다. 사용자 판단이 필요한 항목은 카드 장수·후보·확정 방식, 선택 중 전투 처리, 이번 작업에 실제 보상 반영을 포함할지다.
- **공유 기준** — 이번 업로드의 원격 `main` 기준은 화염 장판 연출과 스킬 코드를 공유한 `7f0b3fc`다. 레벨업 버튼 에셋과 씬, 카드 스크립트 초안, 롤백과 카드 문서는 이 문서를 포함한 커밋으로 공유한다.
