# 사망 재시작 정리와 다음 기능 검토

작성일: 2026-11-12. 현재 코드·씬 참조·기획·마일스톤과 최근 대화를 대조했다. 이번 작업은 문서화이며 코드·게임 에셋 변경, MCP·Notion 사용, 새 실행 검증은 없다.

## 완료한 작업과 해결한 문제

최초 암전 이후에는 기존 적과 플레이어 위치가 그대로여서 스테이지 재시작보다 전투 재개에 가까웠다. ‘보스 게이지만 초기화’라는 표현을 전투 객체까지 보존하는 것으로 해석한 것이 원인이었다. 이후 **성장 데이터 유지와 전투 상태 초기화를 분리**하도록 규칙을 수정했다.

사용자가 작성한 현재 코드는 암전 완료 → 탄환·적·착지 효과 정리 → 같은 Stage.EnterStage 호출 → 시작 위치에서 Revive → 암전 0.5초 유지 → 화면 복구 순서다. 레벨·경험치·스탯·스테이지 번호·목표 처치 수는 유지하며 배경·처치 수·보스 게이지·플레이어 위치/HP/공격 상태를 초기화한다. 기존 적을 제거할 때 Die를 호출하지 않아 초기화 자체로 처치 보상을 지급하지 않는다.

AI는 전환 Canvas·Clear/Cover/Reveal·Controller·종료 이벤트·입력 차단을 제작하고 Stage/Player/ScreenTransition·EnemySpawner·PlayerSpawnPoint 참조를 연결했다. 별도 SpawnInitialEnemies를 추가하지 않고 기존 Update 생성 경로를 재사용한다. 전환 완료 후 첫 생성 시도를 하고 이후 0.5초 간격으로 보충하므로 생성 경로를 중복 관리하지 않는다.

## 확인 결과와 남은 문제

- **사용자 확인:** 연결 후 “지금의 사망 연출은 제대로 구현된 것 같다”고 보고했다. 사망 연출의 사용자 확인으로 기록하며 모든 보존 수치·예외·기기 환경을 개별 검증한 결과로 확대하지 않는다.
- **파일 확인:** Stage의 정리/재시작 호출, Revive의 위치·HP 복구, 공격 대기시간 초기화, 풀 반환, 씬 참조를 대조했다. TryLevelUp은 현재 경험치 차감·레벨 증가·필요 경험치 갱신·HUD 갱신까지만 수행하며 카드 선택 호출은 없다.
- **기존 확인:** 별도 임시 Unity 프로젝트에서 전환 에셋·기존 ScreenTransition 코드의 임포트/컴파일은 성공했다. 원본 게임 전체 검증과 구분한다.
- **남은 문제:** 전환 중 PlayerMotion 일반 행동·SlimeMotion 타이머/Animator 정지, 전환 실패 후 복구 정책, 반복 사망·성장 보존의 항목별 확인은 남았다. 성능 개선 수치는 측정하지 않았다.

## 다음 기능의 우선순위

저장·오프라인 진행과 외부 데이터 관리 체계는 사용자 지시에 따라 후순위로 둔다. 다음 검토 방향은 스킬과 레벨업 카드 선택이다. 새 이미지를 먼저 제작하기보다 임시 UI·텍스트와 기존 공격을 활용해 성장 선택의 흐름을 확인하는 접근을 제안했다. 아직 해당 기능 구현은 시작하지 않았다.

다음 항목은 구현을 위한 **제안이며 확정 규칙이 아니다**: 기존 탄환을 첫 스킬로 취급하기, 카드 3장 구성, 선택 중 전투 정지, 선택 결과의 공격 반영. 카드 후보·최대 강화·경험치 소비 시점 등 세부 규칙은 착수 시 정리한다. 이전 프로젝트의 카드·재추첨·초기화 규칙이나 AI가 제시한 수치를 현재 프로젝트의 확정 규칙으로 자동 승계하지 않는다.

보스 생성·전투·처치 보상·다음 스테이지 연결도 미구현 상태로 유지한다. 이후 하나의 플레이 흐름을 만드는 것이 목표이며, 사용자가 다음 작업을 지정하기 전에는 스킬·카드·보스 중 어느 기능도 자동으로 착수하지 않는다.

## 작업 기준

기능 진행을 막는 오류·이해에 필요한 시각 피드백과 추가 장식 연출을 구분하자는 제안을 논의했다. 이는 전체 이펙트 작업을 중단하거나 모든 세부 연출을 확정한 지시가 아니다. 사용자 주도의 코드 작성·AI의 에셋/연결 보조 역할을 유지한다. 최신 구현 체크는 [마일스톤](../MILESTONES.md), 확정 게임 규칙은 [게임 디자인](../GAME_DESIGN.md)을 따른다.
