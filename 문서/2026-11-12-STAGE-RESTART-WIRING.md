# 같은 스테이지 재시작 참조 연결

작성일: 2026-11-12. 사용자가 수정한 재시작 코드를 확인하고 SampleScene의 참조만 연결했다. C#·Prefab 원본·애니메이션은 수정하지 않았으며 MCP·Notion은 사용하지 않았다.

## 문제와 변경된 의도

이전에는 기존 적 HP·위치와 플레이어 위치를 유지한 채 부활해 잠시 멈춘 전투를 이어가는 모습이었다. 사용자 설명을 다시 확인해 **성장 데이터는 유지하되 같은 스테이지의 전투를 새로 시작**하도록 변경했다. 보스 게이지·처치 수는 초기화하고 목표 처치 수·스테이지 번호·레벨·경험치·스탯은 유지한다. 기존 적·탄환·착지 효과를 정리하고 배경을 다시 배치하며 플레이어 위치·HP·행동 상태를 복구한다. 이전의 적 HP·위치 보존 규칙을 대체한다.

## 현재 코드와 선택 이유

사용자가 Stage.ResetCurrentStage, EnemySpawner.ClearEnemies, Player.Revive(Vector2), 공격 대기시간 초기화와 착지 효과 풀 반환을 작성했다. Stage는 암전 후 정리·EnterStage·Revive를 수행한다. 별도 SpawnInitialEnemies는 추가하지 않는다. 화면 복구 후 기존 EnemySpawner.Update가 첫 생성 시도를 하고 이후 0.5초 간격으로 부족한 수량을 채우므로 중복 생성 경로가 필요하지 않다. 무작위 추첨이므로 이전과 같은 속성·크기의 적이 다시 나올 수도 있다.

## 연결 내용

- Stage 인스턴스 `_enemySpawner` → 기존 EnemySpawner 컴포넌트.
- `PlayerSpawnPoint` 빈 오브젝트 생성 → Stage 인스턴스 `_playerSpawnPoint`에 연결.
- 시작점은 현재 저장된 Player와 같은 부모·같은 위치 `(-0.1, 0.04, 0)`에 배치했다. Player의 자식이 아니므로 플레이어 이동을 따라가지 않는다. 이후 이 오브젝트를 이동해 부활 위치를 조절할 수 있다.

Stage Prefab에 씬 외부 참조를 저장하지 않고 SampleScene의 인스턴스 Override로 연결했다. 기존 전환·HUD·Stage/Player 참조는 유지했다.

## 확인 결과와 남은 확인

후속 사용자 확인: 연결 후 사망 연출이 제대로 구현된 것 같다는 응답을 받았다. 이는 사용자 확인이며 AI의 새 Play 검증이나 아래 항목 전부의 검증 완료를 뜻하지 않는다. [최신 작업 정리·다음 범위](2026-11-12-RESTART-REVIEW-AND-NEXT-SCOPE.md)

씬의 두 참조·시작점 부모/위치·오브젝트 번호 중복 여부를 파일로 확인하고 C# 19개 파일의 해시가 변경되지 않은 것을 대조했다. [연결 검사 결과](검증자료/2026-11-12-사망화면전환/RestartWiring.json). 이번 연결에서는 Unity 임포트·컴파일·Play 검증을 수행하지 않았다.

사용자는 사망 후 시작 위치·HP 복구, 기존 적/탄환 제거, 새 적 생성, 배경 재배치, 보스 게이지 0과 성장 수치 유지를 확인해야 한다. 전환 중 SlimeMotion 정지와 기존 코드의 전환 실패 후 복구 정책은 이번 연결 범위 밖이다. 앞선 [화면 전환 제작 기록](2026-11-12-DEATH-SCREEN-TRANSITION.md)의 기존 적 보존 설명은 이번 변경으로 대체한다.
