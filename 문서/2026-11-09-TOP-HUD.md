# 상단 HUD Hierarchy 구성과 연결

작성일: 2026-11-09. 사용자가 작성한 Player·Stage·PlayerInfo·StageInfo를 수정하지 않고, 승인한 AI 이해안에 맞춰 SampleScene과 UI 에셋을 구성했다.

## 문제·선택한 구성

기존 씬에는 UI 그룹과 월드 공간 HP바만 있어 화면 고정 HUD와 표시 참조가 없었다. HP바는 유지하고 별도 Screen Space Overlay Canvas를 추가했다. Player·Stage는 기존 공개 함수로 UI를 갱신하며, 씬에서 연결한 참조를 사용한다.

```text
UI
├─ EventSystem (기존)
└─ HUDCanvas
   └─ TopHUD
      ├─ PlayerInfoPanel [PlayerInfo]
      │  ├─ NameText
      │  ├─ LevelText
      │  ├─ ExpBar
      │  │  ├─ Fill
      │  │  └─ ExpText
      │  └─ LevelUpButton
      │     └─ Label
      └─ StageInfoPanel [StageInfo]
         ├─ StageNumberText
         ├─ BossBar
         │  └─ Fill
         ├─ BossIcon
         │  ├─ LeftHorn / RightHorn
         │  └─ Head / Face / LeftEye / RightEye
         └─ BossAppearText
```

- 캐릭터 정보는 좌측 상단, Stage 패널은 위쪽 중앙에 배치했다. 경험치 숫자는 바 안에, 작은 보스 아이콘은 게이지 오른쪽 끝 위에 둔다.
- 레벨업 버튼 위치는 시안에 없으므로 캐릭터 패널 아래에 임시 배치했다. 이름 미입력 상태에는 `캐릭터명`을 임시 입력했다.
- CanvasScaler는 Scale With Screen Size, 기준 1080×1920, Match 0.5다. 위치는 상단 앵커와 상대 너비로 구성했다. Canvas 정렬 순서는 200이다.
- 두 게이지는 Filled / Horizontal / Left다. 등장 안내는 진행도 1에서 표시한다. 초기 실제 값은 Lv. 1·0/100·보스 진행도 0이며 시안의 예시 수치를 게임 데이터로 저장하지 않았다.
- 기존 EventSystem을 사용한다. 표시용 Image·텍스트의 Raycast Target을 끄고 버튼만 입력을 받도록 했다.

## 연결한 참조

- PlayerInfo: 이름·레벨·현재/필요 경험치 텍스트, 경험치 Fill, 레벨업 Button.
- Player: `_playerInfo`와 임시 `_playerName`.
- Button On Click: 씬 Player의 `TryLevelUp`을 영구 이벤트로 연결.
- StageInfo: Stage 번호 텍스트, 보스 Fill, 등장 안내 텍스트.
- 씬 Stage 인스턴스: `_stageInfo`를 Prefab override로 연결했다. 씬 HUD 참조를 Stage Prefab 원본에 저장하지 않았다.

## 추가 에셋

- `Assets/UI/TopHUD/`: 단색 텍스처·패널/보스 아이콘용 기본 메시 Sprite·정적 한글 SDF 글꼴.
- 패널과 보스 표시는 단순 UI 도형으로 구성했다. 최초 Sprite 메시 생성 좌표 오류를 픽셀 좌표로 수정한 뒤 실제 화면에서 확인했다.
- TextMeshPro Essential Resources를 임포트했다. 한글 글꼴은 현재 Windows 글꼴에서 필요한 UI 문자·영문·숫자를 정적 아틀라스로 생성했다. 원본 폰트 파일은 복사하지 않았다. 새 한글 이름 등 현재 포함되지 않은 문자는 글꼴 범위를 추가하거나 정식 프로젝트 글꼴로 교체해야 한다.

## 남은 범위

보스 게이지를 채우는 기준·진행 호출·실제 보스 생성은 기존 코드에 없으므로 이번 Hierarchy 작업으로 추가하지 않았다. 레벨업 버튼의 최종 위치, 실제 이름, UI 아트·글꼴의 최종 선정은 남아 있다. 모바일 안전 영역·실기기 검증은 이번 가로/세로 에디터 확인에 포함하지 않는다.

## 후속 오작동 확인과 복구

사용자가 작동하지 않는다고 보고해 재확인했다. 저장된 파일의 컴포넌트 활성 값과 달리, 편집 중인 씬 및 재생 상태에서 PlayerAttack과 EnemySpawner가 모두 비활성이었다. 앞선 격리 시험에서 이 둘을 껐으며, 시험 종료 후 에디터 메모리 상태 정리가 충분하지 않았다. 앞선 함수 직접 호출 검증만으로 일반 전투까지 정상이라고 판단해서는 안 됐다. 이 상태가 유지된 에디터 내부의 정확한 경로는 확정하지 않는다.

- 두 컴포넌트를 다시 활성화하고 씬 저장·재로드로 실제 상태를 확인했다. C#과 보상·성장 규칙은 변경하지 않았다.
- 기능을 끄지 않은 일반 전투 약 19초에 적 5마리, 경험치 20, UI `20 / 100`을 확인했다. 약 48초에는 Lv. 1·경험치 100·레벨업 버튼 활성이었다.
- 버튼 중심의 UI Raycast 결과는 LevelUpButton이었다. UI InputSystem 액션 Point·Click·Submit도 활성 상태였다.
- UI 포인터 클릭 처리 경로로 Lv. 1에서 Lv. 2로 한 레벨 상승하는 것을 확인했다. onClick 직접 호출 검사와 구분한다.
- 가상 마우스를 통한 입력 시험은 Application/EventSystem의 포커스가 없는 상태에서 클릭으로 전달되지 않았다. 해당 시험 장치는 제거했다. 실제 사용자 마우스 입력까지 검증했다고 보고하지 않는다.
- 이번 확인 시 Console 오류·경고는 0개였다. 종료 후 재생을 끄고 두 컴포넌트 활성 상태를 다시 저장·재로드해 확인했다.

보스 게이지의 자동 증가·실제 보스 생성은 여전히 미연결이다. 사용자 최초 보고에서 어떤 UI가 작동하지 않았는지 세부 증상은 확정되지 않았으므로 모든 가능한 UI 문제를 해결했다고 단정하지 않는다.
