# 카메라 추적과 HUD 표시 방식 검토

작성일: 2026-11-18. HUD 1차 수정 후에도 특정 기기에서 UI가 잘 보이지 않는다는 사용자 보고와, 플레이어 추적 카메라에 UI를 부착하자는 제안을 수정 과제로 등록했다. 이번 작업은 문서 등록이며 카메라·Canvas·코드를 변경하지 않는다.

## 요청과 확정 여부

- 목표: 플레이어를 카메라가 따라가면서도 HUD가 화면에 유지되고, 기기별로 패널·글자·아이콘이 읽히는 크기와 비율을 확보한다.
- 제안: HUD를 카메라에 부착하면 카메라 이동과 다양한 화면 크기에 함께 대응할 수 있는지 검토한다.
- 등록 상태: **원인 점검·표시 방식 비교 미착수**. 카메라의 자식으로 이동하거나 Screen Space - Camera로 전환하는 것을 확정한 것은 아니다.

## 기존 기법명과 차이

| 용어·검색어 | 역할 | 이번 문제와의 관계 |
| --- | --- | --- |
| Screen Space - Overlay | 카메라의 월드 위치와 독립적으로 화면 위에 HUD를 표시 | 현재 방식. 카메라가 플레이어를 따라 움직여도 그 이동만으로 HUD가 시야 밖으로 사라지는 구조는 아님. |
| Screen Space - Camera | 지정한 카메라를 기준으로 Canvas를 렌더링 | 비교 후보. Render Camera·Plane Distance·카메라 표시 설정을 함께 확인해야 하며, 카메라의 자식으로 넣는 것과 렌더 모드 변경은 별개. |
| Follow Camera / Player Follow Camera | 월드 카메라가 플레이어 위치를 추적 | 기존 카메라 추적 요청. HUD의 화면비별 배치·배율 조정과 역할을 구분. |
| Canvas Scaler / RectTransform Anchors / Safe Area | UI 배율·배치 공간·기기 안전 영역 조정 | 기기별 잘림·작은 글자·노치 겹침을 확인할 항목. 카메라 부착으로 대체되지 않음. |

이는 기존 용어 안내이며 특정 패키지나 구현 알고리즘을 선택한 것이 아니다.

## 현재 파일 확인과 원인 가설

`Assets/Scenes/IngameScene.unity`의 HUDCanvas는 Overlay, Scale With Screen Size, 기준 1080×1920, Match 0.5이며 Render Camera 참조는 비어 있다. 월드 카메라는 Orthographic Size 7.5와 전체 Viewport를 사용한다. 게임 Scripts에서 카메라 추적·자동 Safe Area 적용 코드는 확인되지 않았다.

기존 상단 Area에는 음수 위치·폭 오프셋이 남아 있고 과거 일부 캡처에 패널 화면 이탈이 기록되어 있다. 이는 점검할 근거이며, 이번에 보고된 모든 기기의 표시 문제를 같은 원인으로 확정하지 않는다. 안 보인다는 현상이 화면 밖 배치·클리핑·비활성·지나친 축소 중 무엇인지도 새 재생 확인이 필요하다.

카메라에 HUD를 부착하는 것만으로 모든 화면비의 크기와 배치를 보장할 수 없다. 현재 Overlay 유지와 Camera 모드 전환을 실제 필요에 따라 비교하고, 배치·배율·Safe Area 문제를 따로 점검하는 방향으로 등록한다. 불필요한 계층 이동과 참조 변경을 줄이고 원인을 구분하기 위한 검토 방식이다.

## 후속 작업과 완료 확인 기준

1. 문제가 있는 기기·해상도·화면비·방향과 가려지는 UI를 확인하고, 현재 Canvas·앵커·Area/Panel·활성/클리핑 상태를 점검한다.
2. Overlay 유지 또는 Camera 모드 적용의 이유를 정한다. Camera 모드가 필요하면 카메라 참조·Plane Distance·클리핑·그리기 순서·입력 경로도 함께 확인한다.
3. 플레이어 추적 카메라와 HUD를 함께 시험한다. 이동·맵 경계·사망 후 복귀 중 HUD의 화면 위치가 유지되는지 확인한다.
4. 문제 기기를 포함한 세로·가로·태블릿 화면에서 패널 내부 비율, 글자 가독성, 버튼 터치, 노치 안전 영역을 확인한다. 같은 픽셀 수나 물리적 cm 크기를 모든 기기에 보장한다는 뜻은 아니다.

최종 기준 해상도·다른 화면비의 여백 정책, 최소 글자/터치 크기, 추가 Safe Area 여백은 별도 결정 사항이다. 기존 스크립트·Prefab·애니메이션 참조와 물리 Transform을 보존하며, 사용자 주도 코드 작업과 에디터 설정 작업을 구분한다.

## 이번 등록의 변경·확인 결과

기존의 HUD 배치 과제에 **카메라 추적과 HUD 렌더 모드의 역할 구분·비교 과제**를 추가했다. 기대 결과는 원인에 맞는 수정과 추적 중 HUD 안정성이며, 실제 수정 효과는 아직 확인하지 않았다. 저장 파일과 코드만 대조했고 MCP·Unity 재생·기기 시험은 수행하지 않았다.
