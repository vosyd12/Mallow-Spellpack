# 플레이어 행동 코드 준비와 남은 애니메이션 연결

작성일: 2026-11-10. 사용자가 작성한 C#을 검토하고 현재 구현 상태를 문서화했다. 이번 문서화에서는 코드·씬·Prefab·클립을 수정하지 않았으며 MCP·Notion을 사용하지 않았다.

## 문제와 원인

클립을 제작하고 Controller에 상태를 등록해도 이동·공격·피격·사망 시점이 전달되지 않으면 재생되지 않는다. 기존 즉시 발사는 Attack 동작의 발사 순간과 일치하지 않았다. 코드 작성 중에는 새 대상 대신 이전 대상을 검사하는 조건, HP 소진과 사망 처리 완료의 혼동, Die 재귀 호출, 구독자가 없을 때의 이벤트 호출 문제가 있었다. 사용자가 수정한 현재 소스에서 해당 문제의 해소를 확인했다.

## 선택한 구조와 이유

- `Player`가 HP와 사망 여부를 관리한다. HP 0에서 `Die()`를 호출하고 `IsDead`로 중복 처리를 막는다. 이동·물리를 중지하고 HP바를 숨긴 후 `Died?.Invoke()`로 알린다. 살아 있는 피격은 `Damaged?.Invoke()`로 전달한다.
- `PlayerAttack`은 유효한 지역 변수 `target`과 사거리를 검사한 뒤 공격 대상을 고정하고 `AttackStarted`를 알린다. 직접 즉시 발사하지 않고 애니메이션 시점의 `MagicAttack()` 호출을 기다린다. `IsAttacking`과 `_hasFired`로 공격 겹침·중복 발사를 방지한다.
- `PlayerMotion`은 이벤트를 구독/해제하고 Idle·Walk·Attack·Hit·Death 상태를 재생한다. `FireProjectile()`은 발사를, `FinishAction()`은 공격/피격 종료와 이동 상태 복귀를 맡는다. 전투 계산과 외형 재생의 책임을 나누기 위한 구조다.
- 슬라임 Death는 기존 코루틴으로 재생 → 클립 길이 대기 → 제거를 표현한다. 대안은 Animation Event·상태 타이머·Unity Awaitable이다. 현재 방식은 실제 종료 감지가 아니므로 재생 클립과 대기용 클립의 일치·Animator 속도 1이 전제다. [연결 기록](2026-11-10-ANIMATION-WIRING.md)

## 달라진 점과 현재 한계

공격 시점과 탄환 생성 시점을 분리했고, HP 소진 이후 이동·공격을 차단하는 코드가 준비됐다. 현재 코드는 공격 중 Hit 동작을 생략하고 기존 피격색만 유지하며 Death는 우선한다. 이는 현재 구현 동작이며 최종 피격 중단 규칙의 확정과 구분한다.

저장된 씬·Prefab에는 `PlayerMotion` 참조가 없고 Attack·Hit의 `m_Events`는 비어 있다. 따라서 **플레이어 애니메이션 연결은 미완료**다. `AttackStarted` 구독자가 없으면 공격을 시작하지 않으며, 시작하더라도 종료 이벤트가 없으면 공격 상태가 해제되지 않는다. 새 이벤트 구조를 기존 자동 공격의 연결 완료로 표시하면 안 된다.

## 남은 연결과 확인 항목

1. Animator와 같은 Visual 오브젝트에 `PlayerMotion`을 부착하고 Player·PlayerAttack·Animator·그림자를 연결한다.
2. Attack 발사 시점에 `FireProjectile()`, Attack·Hit 종료에 `FinishAction()` Animation Event를 등록한다.
3. 실제 이동 전환·공격당 한 발·대상 사망 중 발사 취소·반복 피격·HP 0 이후 공격/이동 중지·Death 재생을 확인한다.
4. Attack 동작의 가독성, 실제 사망 순간 자세와 화면 비율별 이탈, 게임오버·재시작은 별도 미완료 과제다.

## 확인 결과와 재발 방지

소스의 대상 검사·사망 호출·이벤트 구독/해제와 클립의 빈 이벤트 목록을 대조했다. 이번에는 컴파일·Play·모바일 실행·성능 측정을 수행하지 않았다. 예상 효과는 발사 시점 일치와 중복 처리 방지이며 실제 개선 수치나 실행 성공으로 기록하지 않는다.

후속 작업자는 이 문서와 마일스톤에서 코드·필수 참조·클립 이벤트를 각각 확인한다. 연결이 남았으면 전체 기능 완료로 표시하지 않는다. 사용자가 코드를 주도하며 AI의 연결 작업 허가를 코드 수정 허가로 확대하지 않는다.
